# Payroll run and lifecycle wire contracts (MON-082)

## Adopted boundaries

REST paths below are relative to `/api/v1/payroll`. MCP uses direct Drizzle shared services in `lib/api/payroll-runs.ts`, organization-scoped AuthContext and wrapTool; no HTTP self-calls. Strict schemas in payroll-run-wire.ts describe every MCP field. API keys determine their organization, regardless of a conflicting organization header. All operations require manage:payroll except approve/reject, which require approve:payroll and an assigned pending organization member.

| REST operation | MCP operation | Input and result |
|---|---|---|
| GET runs | list_payroll_runs | page, limit, optional status; REST data/pagination; MCP runs/total/page/limit plus additive pagination |
| POST runs | create_payroll_run | payPeriodStart/end, optional regular/off_cycle runType; run with generated items (201 REST) |
| GET runs/:id | get_payroll_run | owned UUID; run/items |
| PATCH runs/:id | update_payroll_run | optional nullable notes, max 10000 characters; run |
| DELETE runs/:id | delete_payroll_run | unapproved draft UUID; success |
| GET runs/:id/items | list_payroll_run_items | owned UUID; items with employeeName, employeeTaxBreakdown and employerTaxBreakdown compatibility names |
| POST runs/:id/process | process_payroll_run | optional accrued boolean, default false; run; MCP also retains journalEntryId |
| POST runs/:id/submit-for-approval | submit_payroll_run_for_approval | empty body; run |
| POST runs/:id/approve | approve_payroll_run | empty body; run |
| POST runs/:id/reject | reject_payroll_run | optional nullable reason; run |
| GET runs/:id/bonuses | list_payroll_run_bonuses | owned run UUID; bonuses with owned employees |
| POST runs/:id/bonuses | create_payroll_run_bonus | employeeId, bonusType, amount/amountMinor, optional nullable description; bonus (201 REST), recalculates payable items |
| DELETE runs/:id/bonuses/:bonusId | delete_payroll_run_bonus | bonus UUID belonging to owned unapproved draft run; success, recalculates payable items |
| POST runs/bonus-only | create_bonus_payroll_run | period, optional notes, 1..200 bonuses with the same bonus fields; run (201 REST) |
| POST runs/termination | create_termination_payroll_run | period, active employeeId, optional includeUnusedPto (false), notes; run (201 REST) |
| POST runs/correction | create_correction_payroll_run | completed parentRunId, optional notes, 1..200 adjustments: employeeId, grossAdjustment/grossAdjustmentMinor, optional description; run (201 REST) |

MCP retains payRunId for the run identifier. REST retains {run}, {bonus}, {bonuses}, {items}, {success} envelopes. Date-only fields are Gregorian YYYY-MM-DD, years 0001..9999, ordered and within one year for new periods. Correction periods copy the parent. Bonus categories: performance, signing, referral, holiday, spot, retention, other. One correction adjustment per employee, nonzero signed gross. Pagination: page 1..1000000; REST limit 1..100; existing MCP limit 1..200 (default 50). Status filters: draft, processing, completed, void, pending_approval. Unknown body fields, malformed JSON, numeric strings in numeric fields, fractions and noncanonical money strings fail explicitly. Bodyless transitions accept no body or {}.

## Units, aliases and range

All existing payroll amounts remain integer cents in their saved currency. Employee amounts use item.currency; new run totals and journal lines use saved baseCurrency, copied from organization.defaultCurrency. Employee currency resolves employee.currency, then payrollSettings.defaultCurrency, then organization currency. No magnitude/locale-based rescaling or reinterpretation of old IRR occurs. This bounded adoption does not enable production IRR.

Numeric amounts coexist with canonical decimal integer strings named FIELDMinor. Run fields: totalGross, totalDeductions, totalNet. Item fields: grossAmount, taxAmount, deductions, netAmount, overtimeAmount, bonusAmount, preTaxDeductions, postTaxDeductions. Breakdown and bonus amount fields gain amountMinor. Nested employee salary/hourlyRate retain MON-079 aliases. Nullable money remains null with a null alias. Numeric inputs and outputs are safe integers, absolute maximum 9007199254740991. String inputs allow signed-int64 syntax, but values outside the supported numeric coexistence range fail 422 before commit; strings do not imply full-int64 runtime support. Both aliases must agree. Bonus cents must be positive; signed corrections must be nonzero. Negative zero, plus prefixes, leading zeroes, whitespace, exponent/fraction syntax and localized digits are rejected. Responses contain no bigint.

Hours/PTO/premiums retain numeric binary32 units from MON-081: finite, nonnegative, no negative zero and representable without storage rounding, max safe numeric value. Rates in basis points remain 0..10000; deduction percents remain decimal percentages 0..100 with exact binary32 representation (e.g. 2.5). FX is a separate decimal multiplier, not cents, basis points or scaled millionths.

Saved item rateExact is canonical positive decimal, at most 20 whole and 18 fraction digits, quote_per_base from employee currency to saved run currency, format version 1, status exact. fxRate remains an explicitly approximate numeric binary32 compatibility field; PostgreSQL shortest float4 text is recovered to its stored binary32 value before serialization. It is never used for adopted monetary arithmetic. New JSON provenance uses payroll_exact_v1, currency pair, as-of/effective date, provider/source/inverse metadata; corrections preserve parent provenance. Missing, quarantined, unsupported or incoherent FX fails explicitly. Pending legacy real snapshots can bridge only if their actual binary32 rational fits the exact decimal policy; 1.25 does, binary32 1.2 does not. Historical exact decimal snapshots remain authoritative after current exchange-rate changes.

## Arithmetic and posting

Salary divides annual cents by 12/26/52 with bigint rational intermediates. Hourly approved timesheets contribute only entry dates inside both the run and sheet bounds; approved sheets must overlap the period. With no approved sheets, existing 40/80/173 hour defaults remain. Existing overtime threshold applies per run, not a newly inferred weekly statute. Hours and overtime wages use exact binary32 rational units. Every final rational cent result rounds half away from zero, including negative corrections; no floating monetary multiplication or Math.round remains in adopted services.

Tax annualization, allowances, progressive brackets, FICA and employer caps use bigint intermediates. Requested default tax year, default federal jurisdiction and status-specific schedules are selected as whole sets, falling back only to year-agnostic brackets. Bracket bands must be ordered/unambiguous. Duplicate, overlapping, missing bands, unsafe data or withholding exceeding available wages fail. Flat employee basis-point fallback retains additional withholding. Existing employee schema lacks elected state/local jurisdiction, so this change uses its existing federal/default and configured employer SUTA parameters; it does not invent statutory rates or new compliance policy. YTD includes owned, nondeleted completed/processing runs ending before the period start in the same year.

Recurring deductions honor assignment/type activity and effective dates. Fixed cents take precedence over percent. One-time assignments reserve one live draft and are consumed with posting, never merely with creation. Deletion releases an unconsumed reservation. Deduction liability codes and assignment IDs are snapshotted. Bonuses group withholding once per employee and allocate exact tax components to pay capacities. Draft bonus edits rebuild actual items and totals while preserving base wage and historical FX. Termination salary uses inclusive period days / 365 rounded once; hourly final pay retains its existing 80-hour default. PTO uses hourly cents or annual salary / 2080. PTO deduction, deactivation and termination date occur only on completion; approval leaves employee state untouched.

Corrections preserve each parent's employee currency/FX and proportionally signed per-employee tax, employer tax and deduction snapshots. Mixed parent currency/rate or missing ambiguous deduction detail fails. Posted parent history is never edited. A missing legacy tax breakdown falls back only to that employee's saved withholding, never the whole run's proportions.

Run gross and deductions convert each item exactly once; run net is converted gross minus converted deductions. Component FX residual is assigned to the largest employee liability bucket (account-code tie break). Posting validates saved totals, detail sums, account ownership/activity/type/currency and journal balance before writing. Gross wages debit 5100; employer taxes debit 5120; liabilities use tax/deduction kinds, never VAT control 2200; net credits configured bank/fallback 1100 or accrued wages payable 2310. Signed corrections flip the appropriate side. Journal amounts use saved base currency and exact 1:1 FX.

## State, safety and migration

Only unapproved drafts can be edited/deleted; posted runs require correction. Regular/off_cycle creation stays draft. Bonus/termination/correction auto-complete when no active approval chain exists and otherwise stay draft for submission. Submission requires exactly one nonempty active chain of owned members. Pending submissions retry without duplicate records; rejected rounds can be edited and resubmitted. Assigned actors approve/reject; all recorded approvers must approve before processing. Completed process retries, including concurrent REST/MCP requests or a changed accrued option, return the existing result without another journal/audit or employee side effect. Other new-run creation calls represent new economic events, not idempotent payment requests. Repeating an approval decision without a pending record returns 409.

Writes take organization and relevant employee/run locks; mutation, numbering, accounts, journal, state and audit share one database transaction. Response preflight runs before commit. Reads use repeatable-read snapshots and validate all nested employee/project/milestone/timesheet/deduction tenant references. Invalid input is REST 400 (SDK validation errors for MCP); missing/foreign rows 404; permissions 401/403; conflicting lifecycle 409; unsupported money/FX, locked periods and unsafe saved outputs 422. Unexpected database faults return generic 500 without committing partial effects. Existing fiscal/period locks apply to posting.

Generated migration 0009_melodic_bullseye adds nullable run base currency/termination intent and deduction assignment/liability snapshots. It replaces only payroll_item FX guards with one payroll-aware trigger: new adopted decimal snapshots must match binary32 approximation and saved currency pair; adopted provenance/rates are immutable. Legacy writers and backfill retain lossless reconstruction/quarantine behavior. No historical rows, amounts, dates, rates or migration states are rewritten; old nullable fields remain null. Organization currency changes are blocked with any payroll history, coordinating with existing master currency guards. Apply committed migrations before using these operations; no production migration was executed for this task.

No build, dev server, browser screenshots, hosted CI, provider, production or accounting sign-off was performed.

# AI-005 - Meter token usage costs and enforce concurrent budgets

## Objective and implementation scope

Implement usage records, pricing snapshots, budget reservations and reporting services independent of the dashboard.

This task implements the owner-requested AI feature; it does not authorize deployment or relax existing financial/release gates.

## Inputs

- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Architecture and delivery plan](../docs/AI_AGENT_PLAN.md).
- Actual source and dependency evidence; verify current contracts before editing.

## Acceptance criteria

- [ ] Record each provider attempt by organization, user, run, provider and model with input/output/cached/reasoning token fields when available; unknown usage remains unknown and retries are not lost or double counted.
- [ ] Calculate estimated cost with exact decimal or fixed-point arithmetic and versioned prices, explicit billing currency and no cross-currency summation; distinguish estimates from provider invoices.
- [ ] Enforce per-user and organization token/cost quotas, rate/concurrency limits and per-run ceilings using atomic reservations and settlement; handle cancellations and delayed or missing usage conservatively.
- [ ] Scoped REST/MCP usage and budget APIs pass aggregation, concurrent-reservation, retry, quota exhaustion and access-control tests.

## Verification

Run meaningful focused checks for the changed contracts, including real REST/MCP authorization and disposable-database integration where relevant. Use typecheck and lint for application changes, catalog validation for localized UI, controller validation and diff checks. No full build or unrequested dev server. Record executed checks and limitations in unique evidence; do not substitute mocked-provider success for live-provider qualification.

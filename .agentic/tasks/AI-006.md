# AI-006 - Build authorized domain tool registry and guarded dispatch

## Objective and implementation scope

Reuse existing MCP operations and shared business services to dispatch only explicitly supported capabilities.

This task implements the owner-requested AI feature; it does not authorize deployment or relax existing financial/release gates.

## Inputs

- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Architecture and delivery plan](../docs/AI_AGENT_PLAN.md).
- Actual source and dependency evidence; verify current contracts before editing.

## Acceptance criteria

- [ ] Expose only allowlisted tools within the intersection of user permission, organization policy and agent policy; no arbitrary SQL, shell, code execution or arbitrary URL tools.
- [ ] Validate strict schemas and exact minor-unit strings/currency/date contracts; preserve period locks, plan limits, approval workflows and audit attribution to the initiating user.
- [ ] Publish domain coverage and gaps against AI-001; create bounded follow-up tasks for uncovered site capabilities before claiming full coverage, with real registered MCP and service tests.
- [ ] Test denied reads and writes, malicious tool arguments and tool-result error handling; tool errors cannot be treated as successful business actions.

## Verification

Run meaningful focused checks for the changed contracts, including real REST/MCP authorization and disposable-database integration where relevant. Use typecheck and lint for application changes, catalog validation for localized UI, controller validation and diff checks. No full build or unrequested dev server. Record executed checks and limitations in unique evidence; do not substitute mocked-provider success for live-provider qualification.

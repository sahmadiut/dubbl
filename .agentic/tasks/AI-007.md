# AI-007 - Implement durable bounded multi-step agent execution

## Objective and implementation scope

Implement the server-side model/tool loop with persisted events and a fake provider for deterministic verification.

This task implements the owner-requested AI feature; it does not authorize deployment or relax existing financial/release gates.

## Inputs

- [Product experience contract](../docs/AI_PRODUCT_EXPERIENCE.md): normative journeys, UI states and observable UX acceptance.
- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Architecture and delivery plan](../docs/AI_AGENT_PLAN.md).
- Actual source and dependency evidence; verify current contracts before editing.

## Acceptance criteria

- [x] A request can discover records, invoke multiple dependent tools, observe results and produce a grounded final answer with links to resulting records; clarify ambiguous IDs or missing required data.
- [x] Enforce step, token, cost, elapsed-time and tool-output limits; support stop, timeout, provider failure, bounded transient retries and disconnected-client recovery.
- [x] Recover durable runs without duplicate side effects using operation-level idempotency and reconciliation of uncertain outcomes; dependent writes are ordered and partial completion is explicit.
- [x] Treat user content, documents and tool output as untrusted data; they cannot alter authorization or tool policy. Export user-facing action summaries and events without private model reasoning.
- [x] Run lifecycle REST/MCP operations share services; cancellation, race conditions and multi-tool completion pass deterministic integration tests.

- [x] Independently integrate the AI-023 user-facing state contract: persisted clarification/resume, scoped progress content, safe result links, cancellation acknowledgement and completed/failed/not-started/uncertain summaries. Verify reconnect never replays a request and UI/MCP can consume each state without inventing an action.

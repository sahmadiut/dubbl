## پروتکل MCP چیست؟

[پروتکل کانتکست مدل](https://modelcontextprotocol.io) (Model Context Protocol یا MCP) یک استاندارد باز است که به عامل‌ها و دستیارهای کدنویسی هوش مصنوعی اجازه می‌دهد با ابزارها و منابع داده خارجی تعامل داشته باشند. سرور داخلی MCP در dubbl به هر عامل سازگار با MCP دسترسی مستقیم به داده‌های حسابداری شما را می‌دهد — از جمله ثبت اسناد، مدیریت فاکتورها، تولید گزارش‌ها و موارد دیگر.

## پیش‌نیازها

- **هر پلنی** -- دسترسی به MCP در تمام پلن‌ها، از جمله پلن رایگان (Free)، امکان‌پذیر است
- هر کلاینت سازگار با MCP (مانند Claude Desktop، Claude Code، Cursor، Windsurf، Cline، VS Code Copilot یا سایر عامل‌های مجهز به MCP)

## اتصال عامل شما

هر عامل سازگار با MCP می‌تواند به سرور MCP در dubbl متصل شود. این سرور از روش انتقال Streamable HTTP در مسیر `/api/mcp` و استاندارد OAuth 2.1 برای احراز هویت استفاده می‌کند. اکثر عامل‌ها جریان OAuth را به‌صورت خودکار مدیریت می‌کنند — آن‌ها در اولین اتصال، یک پنجره مرورگر را باز می‌کنند تا وارد حساب کاربری خود شوید و مجوز دسترسی را صادر کنید.

مثال‌های زیر از `https://dubbl.dev/api/mcp` استفاده می‌کنند. در صورت استفاده از نسخه میزبانی شخصی (سلف‌هاست)، `dubbl.dev` را با دامنه اختصاصی خود جایگزین کنید.

### Claude Desktop

این پیکربندی را به فایل تنظیمات Claude Desktop خود (`claude_desktop_config.json`) اضافه کنید:

```json
{
  "mcpServers": {
    "dubbl": {
      "url": "https://dubbl.dev/api/mcp"
    }
  }
}
```

### Claude Code

```bash
claude mcp add dubbl --transport streamable-http https://dubbl.dev/api/mcp
```

### Cursor

به مسیر **Cursor Settings > MCP** بروید و یک سرور جدید اضافه کنید، یا آن را در فایل `.cursor/mcp.json` پروژه خود قرار دهید:

```json
{
  "mcpServers": {
    "dubbl": {
      "url": "https://dubbl.dev/api/mcp"
    }
  }
}
```

محیط Cursor به‌طور خودکار انتقال Streamable HTTP را از روی URL شناسایی کرده و فرآیند OAuth را مدیریت می‌کند.

### Windsurf

به مسیر **Windsurf Settings > Cascade > MCP** بروید و روی **View raw config** کلیک کنید، یا فایل `~/.codeium/windsurf/mcp_config.json` را مستقیماً ویرایش کنید:

```json
{
  "mcpServers": {
    "dubbl": {
      "serverUrl": "https://dubbl.dev/api/mcp"
    }
  }
}
```

### VS Code (GitHub Copilot)

این تنظیمات را به فایل `.vscode/mcp.json` در فضای کاری خود اضافه کنید (در VS Code نسخه ۱.۹۹ به بالا در دسترس است):

```json
{
  "servers": {
    "dubbl": {
      "type": "http",
      "url": "https://dubbl.dev/api/mcp"
    }
  }
}
```

یا آن را به فایل `settings.json` کاربری خود اضافه کنید تا در تمامی فضاهای کاری فعال باشد:

```json
{
  "mcp": {
    "servers": {
      "dubbl": {
        "type": "http",
        "url": "https://dubbl.dev/api/mcp"
      }
    }
  }
}
```

### سایر کلاینت‌های MCP

هر عاملی که از انتقال MCP Streamable HTTP پشتیبانی کند، می‌تواند متصل شود. کافی است آن را به نشانی زیر هدایت کنید:

```
https://dubbl.dev/api/mcp
```

کلاینت به‌صورت خودکار اندپوینت‌های OAuth را از طریق اندپوینت متادیتای `/.well-known/oauth-authorization-server` شناسایی خواهد کرد.

## جریان OAuth

سرویس dubbl از پروتکل OAuth 2.1 به همراه PKCE برای احراز هویت MCP استفاده می‌کند:

۱. کلاینت MCP نقاط پایانی OAuth را از طریق `/.well-known/oauth-authorization-server` روی نقطه پایانی MCP شناسایی می‌کند
۲. کلاینت به‌صورت پویا در `/api/mcp/oauth/register` ثبت‌نام می‌کند
۳. کلاینت شما را برای ورود به سیستم به `/api/mcp/oauth/authorize` هدایت می‌کند
۴. شما یک سازمان را انتخاب کرده و اتصال را تأیید می‌کنید
۵. کلاینت یک کد مجوز دریافت کرده و آن را در `/api/mcp/oauth/token` با توکن‌های دسترسی/تازه‌سازی مبادله می‌کند
۶. توکن‌های دسترسی پس از ۱ ساعت منقضی می‌شوند؛ توکن‌های تازه‌سازی ۳۰ روز اعتبار دارند

## ابزارهای موجود

### سازمان
- `get_organization` -- دریافت جزئیات سازمان فعلی

### کارکنان حقوق و دستمزد و پیمانکاران

- `list_payroll_employees` -- فهرست و فیلتر کردن کارکنان فعال
- `get_payroll_employee` -- خواندن اطلاعات کارمند و پروفایل عضو پیوندیافته ایمن
- `create_payroll_employee` -- ایجاد کارمند با حقوق سالانه
- `update_payroll_employee` -- ویرایش کارمند با حفظ سوابق حقوق و دستمزد
- `delete_payroll_employee` -- حذف نرم یک کارمند
- `list_contractors` -- فهرست و فیلتر کردن پیمانکاران فعال
- `get_contractor` -- خواندن اطلاعات پیمانکار و پرداخت‌های قبلی
- `create_contractor` -- ایجاد پیمانکار با نرخ ساعتی اختیاری
- `update_contractor` -- ویرایش پیمانکار با حفظ سوابق پرداخت
- `delete_contractor` -- حذف نرم یک پیمانکار

عملیات مربوط به کارکنان نیازمند مجوز `manage:payroll` و عملیات پیمانکاران نیازمند
`manage:contractors` است. حقوق سالانه به‌صورت عدد صحیح سنت و نرخ ساعتی به‌صورت سنت در
ساعت است. فیلدهای عددی و رشته‌های منطبق `salaryMinor` / `hourlyRateMinor` تا سقف
۹۰۰۷۱۹۹۲۵۴۷۴۰۹۹۱ پشتیبانی می‌شوند؛ مقدار null نرخ ساعتی را پاک می‌کند. پرداخت‌های جزئیات
پیمانکار، `amountMinor` را بر حسب ارز هر پرداخت اضافه می‌کنند. نرخ مالیات بر حسب نقاط پایه (basis points)،
مرخصی استحقاقی (PTO) بر حسب ساعت و تاریخ‌ها میلادی هستند. تغییر ارز نیازمند عدم وجود اقلام
حقوق/پرداخت‌های فعلی است؛ این ابزارها حقوق و دستمزد را ثبت قطعی نکرده و ارزها را تبدیل نمی‌کنند.

### سرفصل حساب‌ها
- `list_accounts` -- فهرست کردن تمام حساب‌ها با فیلتر اختیاری نوع حساب
- `get_account` -- دریافت حساب همراه با مانده محاسبه‌شده
- `create_account` -- ایجاد یک حساب جدید
- `update_account` -- به‌روزرسانی جزئیات حساب
- `delete_account` -- حذف حساب (در صورت وجود تراکنش با شکست مواجه می‌شود)

### اسناد حسابداری
- `list_entries` -- فهرست کردن اسناد با فیلترهای وضعیت/تاریخ
- `get_entry` -- دریافت سند همراه با ردیف‌ها
- `create_entry` -- ایجاد سند جدید (مجموع بدهکار باید با بستانکار برابر باشد)
- `post_entry` -- ثبت قطعی سند پیش‌نویس
- `void_entry` -- باطل کردن سند ثبت‌شده (ایجاد سند معکوس)

### مخاطبین
- `list_contacts` -- جستجو و فیلتر کردن مخاطبین
- `get_contact` -- دریافت جزئیات مخاطب
- `create_contact` -- ایجاد مشتری، تأمین‌کننده یا هر دو
- `update_contact` -- به‌روزرسانی جزئیات مخاطب

### فاکتورهای فروش
- `list_invoices` -- فهرست فاکتورها با فیلترها
- `get_invoice` -- دریافت فاکتور همراه با ردیف‌ها
- `create_invoice` -- ایجاد فاکتور با ردیف‌ها
- `void_invoice` -- باطل کردن فاکتور
- `pay_invoice` -- ثبت پرداخت (مبلغ بر حسب سنت)

### فاکتورهای خرید
- `list_bills` -- فهرست فاکتورهای خرید با فیلتر وضعیت
- `create_bill` -- ایجاد فاکتور خرید با ردیف‌ها
- `get_bill` -- دریافت جزئیات فاکتور خرید با نام‌های مستعار دقیق پولی و نمایش ارز پایه
- `get_bill_counts` -- شمارش تعداد فاکتورهای خرید و مبلغ سررسیدشده بر اساس وضعیت و ارز
- `update_bill` -- ویرایش سربرگ فاکتور خرید پیش‌نویس یا جایگزینی اتمیک ردیف‌ها
- `delete_bill` -- حذف نرم فاکتور خرید پیش‌نویس به‌صورت اتمیک
- `receive_bill` -- دریافت پیش‌نویس با ثبت اتمیک در دفتر کل، موجودی کالا و GRNI
- `approve_bill` -- تأیید فاکتور خرید در انتظار با ثبت اتمیک پس از تأیید نهایی
- `reject_bill` -- رد فاکتور خرید در انتظار و بازگرداندن به پیش‌نویس همراه با ردپای حسابرسی
- `pay_bill` -- ثبت پرداخت (مبلغ بر حسب سنت)
- `void_bill` -- باطل کردن فاکتور خرید تسویه‌نشده با استفاده از مقادیر ذخیره‌شده دفتر کل، نرخ ارز و موجودی کالا

### اعلامیه‌های بدهکار تأمین‌کننده
- `list_debit_notes` -- فهرست اعلامیه‌های تأمین‌کننده با مقادیر پولی عددی ایمن و نام‌های مستعار دقیق
- `get_debit_note` -- خواندن اطلاعات تأمین‌کننده، ردیف‌ها و سند شناسایی حسابداری
- `create_debit_note` -- ایجاد پیش‌نویس؛ قیمت‌های عددی واحدهای فرعی عدد صحیح هستند
- `update_debit_note` -- ویرایش پیش‌نویس یا جایگزینی اتمیک ردیف‌های آن
- `delete_debit_note` -- حذف نرم پیش‌نویس و حفظ ردیف‌های آن
- `send_debit_note` -- شناسایی بستانکاری حساب‌های پرداختنی (AP) و برگشت‌های کامل و واجد شرایط موجودی کالا
- `apply_debit_note` -- تهاتر فاکتورهای خرید شناسایی‌شده با تأمین‌کننده، ارز و نرخ ارز دفتری منطبق
- `void_debit_note` -- برگشت سند/موجودی ذخیره‌شده و بازگردانی تخصیص‌های حامل

در اعلامیه بدهکار، `unitPriceExact` به‌صورت واحدهای اصلی اعشاری و `unitPriceMinor` به‌صورت
واحدهای فرعی عدد صحیح است؛ نام‌های مستعار ترکیبی باید همخوانی داشته باشند. قیمت‌های عددی واحدهای
فرعی عدد صحیح (سنت دلار آمریکا) باقی می‌مانند. مبالغ و مقادیر مشتق‌شده باید در محدوده اعداد صحیح
ایمن قرار گیرند. ارسال، صرفاً شناسایی حسابداری را انجام می‌دهد؛ برای تحویل از `send_document_email`
استفاده کنید. برگشت‌های جزئی/GRNI موجودی کالا و تسویه با نرخ‌های ارز دفتری متفاوت، وضعیت احراز صلاحیت معلق را رد می‌کنند.

### درخواست‌های خرید

- `get_purchase_requisition` -- دریافت جزئیات با نام‌های مستعار دقیق پولی
- `update_purchase_requisition` -- ویرایش تأمین‌کننده/تاریخ/شماره پیگیری/یادداشت‌های پیش‌نویس
- `delete_purchase_requisition` -- حذف نرم پیش‌نویس با حفظ ردیف‌ها
- `submit_purchase_requisition` -- ارسال پیش‌نویس جهت تأیید
- `approve_purchase_requisition` -- تأیید درخواست ارسال‌شده
- `reject_purchase_requisition` -- رد درخواست ارسال‌شده همراه با ذکر دلیل
- `convert_purchase_requisition` -- کپی مقادیر ذخیره‌شده تأییدشده به یک سفارش خرید (PO) پیش‌نویس

### سفارش‌های خرید

- `create_purchase_order` -- ایجاد پیش‌نویس به همراه نام‌های مستعار دقیق قیمت به واحدهای اصلی/فرعی
- `list_purchase_orders` -- فهرست کردن سفارش‌های محدوده‌بندی‌شده، تامین‌کننده و اقلام
- `get_purchase_order` -- دریافت جزئیات سفارش با نام‌های مستعار پولی دقیق
- `get_purchase_order_counts` -- شمارش و جمع کل سفارش‌ها بر اساس وضعیت و واحد پول
- `update_purchase_order` -- ویرایش یکپارچه (اتمیک) یک پیش‌نویس با خط‌مشی مالیاتی قدیمی PATCH

- `send_purchase_order` -- علامت‌گذاری به‌عنوان ارسال‌شده و ارسال اختیاری ایمیل پس از ثبت قطعی (commit)

### گزارش‌ها

- `profit_and_loss` -- صورت سود و زیان با بازه تاریخی

- `aged_payables` -- بازه‌های سنی حساب‌های پرداختنی (AP)

## قراردادهای مبالغ

- تمام مبالغ پولی در ورودی‌ها و خروجی‌های ابزار بر حسب **سنت به صورت عدد صحیح** هستند (مثلاً `1250` = ۱۲٫۵۰ دلار)
- در عملیات ثبت فاکتور/صورت‌حساب/سفارش خرید/درخواست خرید، `unitPrice` به صورت واحدهای اصلی اعشاری است (۱۲٫۵۰ دلار)؛ `unitPriceExact` یک رشته اعشاری دقیق واحد اصلی و `unitPriceMinor` یک رشته عددی صحیح واحد فرعی است. مقدار (Quantity) به صورت واحدهای فیزیکی اعشاری بیان می‌شود. پاسخ‌های ثبت صورت‌حساب شامل نام‌های مستعار دقیق سربرگ `*Minor` هستند؛ مبالغ پشتیبانی‌شده به صورت اعداد صحیح امن علامت‌دار (signed safe integers) باقی می‌مانند. برای خط‌مشی‌های مربوط به واحد پول، گرد کردن و موارد تکراری به [مرجع API](/docs/api-reference) مراجعه کنید.
- نرخ‌های برابری ارز به صورت اعداد صحیح با ۶ رقم اعشار ذخیره می‌شوند (`1000000` = ۱٫۰)

## تست و ارزیابی

### با MCP Inspector

ابزار [MCP Inspector](https://github.com/modelcontextprotocol/inspector) ساده‌ترین راه برای تست تعاملی سرور MCP در طول فرآیند توسعه است.

```bash
# ابتدا سرور توسعه را راه‌اندازی کنید
pnpm dev

# بازرس MCP را متصل به نمونه محلی خود اجرا کنید
npx @modelcontextprotocol/inspector --url http://localhost:3000/api/mcp
```

بازرس در مرورگر شما باز خواهد شد و شما را در فرآیند OAuth راهنمایی می‌کند. پس از احراز هویت، می‌توانید ابزارهای موجود را مرور کرده، آن‌ها را با ورودی‌های سفارشی فراخوانی کنید و پاسخ‌های JSON-RPC را بررسی نمایید.

### فرآیند دستی OAuth

اگر می‌خواهید فرآیند OAuth را مرحله به مرحله تست کنید:

**۱. بررسی کشف متادیتا**

```bash
curl http://localhost:3000/.well-known/oauth-authorization-server/api/mcp
```

این فراخوانی باید ساختاری JSON حاوی نشانی تمام اندپوینت‌های OAuth بازگرداند.

**۲. ثبت یک کلاینت**

```bash
curl -X POST http://localhost:3000/api/mcp/oauth/register \
  -H "Content-Type: application/json" \
  -d '{"redirect_uris": ["http://localhost:9999/callback"], "client_name": "Test Client"}'
```

مقدار `client_id` را از پاسخ ذخیره کنید.

**۳. آغاز فرآیند احراز مجوز**

این نشانی را در مرورگر خود باز کنید (مقدار `CLIENT_ID` را با مقدار به‌دست‌آمده از مرحله ۲ جایگزین کنید):

```
http://localhost:3000/api/mcp/oauth/authorize?client_id=CLIENT_ID&redirect_uri=http://localhost:9999/callback&code_challenge=TEST_CHALLENGE&code_challenge_method=S256&state=test123&response_type=code
```

ابتدا برای ورود به سیستم (در صورت نیاز) و سپس به صفحه اعلام رضایت هدایت خواهید شد. پس از تایید، همراه با پارامتر `code` به نشانی callback ارجاع داده می‌شوید.

**۴. مبادله کد با توکن‌ها**

```bash
curl -X POST http://localhost:3000/api/mcp/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "authorization_code",
    "code": "THE_CODE_FROM_STEP_3",
    "redirect_uri": "http://localhost:9999/callback",
    "client_id": "CLIENT_ID",
    "code_verifier": "THE_VERIFIER_MATCHING_YOUR_CHALLENGE"
  }'
```

این درخواست مقادیر `access_token` و `refresh_token` را برمی‌گرداند.

**۵. فراخوانی اندپوینت MCP**

```bash
curl -X POST http://localhost:3000/api/mcp \
  -H "Authorization: Bearer mcp_at_YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
```

## وارد کردن صورت‌حساب خرید از طریق CSV

از `get_import_template` با مقدار `entityType: "bills"` استفاده کنید، سپس `preview_bill_import` و `import_bills` را همراه با سطرهای نگاشت‌شده مسطح (flat mapped) به کار بگیرید. قیمت‌ها و مقادیر بازنویسی‌شده مبلغ کل سطر در REST و MCP از واحدهای اعشاری **اصلی** (major) استفاده می‌کنند. مقادیر `lineUnitPriceExact`/`lineAmountExact` رشته‌های اعشاری بر مبنای واحد اصلی هستند؛ `lineUnitPriceMinor`/`lineAmountMinor` رشته‌های عدد صحیح بر مبنای واحد فرعی ارز هستند. مقادیر هم‌ارز (aliases) باید کاملاً مطابقت داشته باشند؛ مبالغ پولی، کالاها و مجموع‌های گروهی باید در محدوده اعداد صحیح امن (safe integers) قرار گیرند. ارز پیش‌فرض USD است؛ نام‌ها و حساب‌ها در سطح سازمان فعلی تطبیق داده می‌شوند.

مقدار غیرخالی `billNumber` سطرها را گروه‌بندی می‌کند؛ عدم ارسال یا خالی بودن آن صورت‌حساب‌های خرید جداگانه‌ای ایجاد می‌کند. عملیات واردسازی نیازمند دسترسی `manage:bills` و پارامتر `fileName` است، دوره‌های مالی را بررسی می‌کند و هر پیش‌نویس، شماره، سطرها و لاگ حسابرسی ایجاد (create audit) را به‌صورت یکپارچه و اتمیک ثبت (commit) می‌نماید. در تسک بازگردانده‌شده، مقدار totalRows تعداد سطرهای ورودی را می‌شمارد؛ مقادیر processedRows/errorRows اسناد را شمارش می‌کنند. ممکن است بخشی از پردازش‌ها ناموفق باشد؛ تکرار عملیات، صورت‌حساب‌های جدیدی ایجاد می‌کند. پیش‌نمایش (Preview) هیچ داده‌ای در پایگاه داده ثبت نمی‌کند و اعتبارسنجی سطربه‌سطر را همراه با مقادیر عددی ذخیره‌شده واحد فرعی به‌علاوه رشته‌های با نام `*Minor` برمی‌گرداند. هیچ ثبتی در دفتر کل یا پرداخت انجام نمی‌شود؛ احراز صلاحیت ارز در سطح تولید/int64 به‌صورت مستقل باقی می‌ماند.

## ابزارهای دسته‌بندی بانکی

از `categorize_bank_transaction` برای یک دسته‌بندی منفرد یا از `split_bank_transaction` برای تخصیص‌های دقیق استفاده کنید. در تفکیک، مقدار `amount` یک عدد صحیح بر مبنای واحد فرعی ارز بانک (سنت در USD) است؛ `amountMinor` نام مستعار رشته‌ای دقیق آن به‌صورت عدد صحیح است. هر دو باید با یکدیگر همخوانی داشته باشند. مجموع تخصیص‌ها باید دقیقاً برابر با قدر مطلق تراکنش ثبت‌شده بانکی باشد. تکرار یک دسته‌بندی ساده، سند روزنامه مربوطه را با نرخ تبدیل ارز (FX) ذخیره‌شده تصحیح می‌کند؛ تکرار تفکیک‌ها با خطا مواجه خواهد شد.

ابزار `bulk_cash_code` تا ۲۰۰ تراکنش را به یک حساب کدگذاری می‌کند؛ `bulk_categorize_bank_transactions` حساب‌ها و ابعاد (dimensions) را به‌ازای هر آیتم به‌صورت مجزا می‌پذیرد. هر آیتم به‌صورت مستقل ثبت (commit) می‌شود، خطاها گزارش می‌گردند و در تلاش‌های مجدد هیچ ثبت تکراری صورت نخواهد گرفت. این ابزارها به دسترسی `manage:banking` نیاز دارند.

ابزار `create_expense_from_bank_transaction` به دسترسی `manage:expenses` نیاز دارد و یک تراکنش خروجی را به‌عنوان یک ادعای هزینه (expense claim) از پیش پرداخت‌شده و متصل به سند روزنامه ثبت می‌کند. مقدار عددی آیتم `amount` از واحدهای فرعی عدد صحیح استفاده می‌کند (برای مثال ۱۲۵۰ در USD معادل ۱۲٫۵۰ دلار است)، `amountMinor` یک رشته عدد صحیح و `amountExact` یک رشته اعشاری بر مبنای واحد اصلی («12.50») است. تمامی نام‌های مستعار باید تطابق داشته باشند؛ ارز و مبلغ کل باید با اطلاعات بانک همخوانی داشته باشند. این ابزار `expenseClaim` را همراه با `totalAmount` عددی، `totalAmountMinor` دقیق و `journalEntryId` بازمی‌گرداند. ایجاد مجدد و تکراری با خطا مواجه می‌شود. مقادیر پولی و مجموع‌های قابل ثبت تا ۹۰۰۷۱۹۹۲۵۴۷۴۰۹۹۱ واحد فرعی پشتیبانی می‌شوند؛ ورودی‌های دقیقِ فراتر از این محدوده، به‌جای گرد شدن، صراحتاً با خطا رد می‌شوند.

## ابزارهای تطبیق اسناد بانکی

ابزارهای `match_to_invoice` و `match_to_bill` یک سطر کامل از صورت‌حساب بانکی دریافتی/پرداختی را تسویه می‌کنند. ابزار `split_to_documents` آن را بین فاکتورها/صورت‌حساب‌های شناسایی‌شده مجزا متعلق به همان مخاطب/ارز تخصیص می‌دهد. مقدار عددی `amount` به معنای واحدهای فرعی صحیح ارز است (USD 1250 = $12.50)؛ و `amountMinor: "1250"` نام مستعار دقیق و استاندارد آن است. این مقادیر باید همخوانی داشته باشند و کل سطر را پوشش دهند؛ پوشش جزئی، ترکیب چند مخاطب/ارز و پرداخت‌های اضافی با خطا مواجه می‌شوند. تاریخ اختیاری به‌طور پیش‌فرض تاریخ صورت‌حساب است؛ روش پرداخت به‌طور پیش‌فرض روی bank_transfer قرار دارد. به مجوز `manage:banking` نیاز دارد.

پرداخت، سند حسابداری تسعیر ارز دفتری/نقدی ذخیره‌شده، تخصیص، به‌روزرسانی اسناد، پیوندهای بانکی و لاگ‌های حسابرسی به‌صورت یکپارچه ثبت (commit) می‌شوند. پاسخ‌ها شامل transactionId، پرداخت و وضعیت سند هستند؛ پرداخت مقادیر amount/amountMinor/currencyCode/journalEntryId را اضافه می‌کند. نتایج تقسیم شامل تخصیص‌ها به همراه amount/amountMinor/newStatus است. حامل‌های غیرنقدی بستانکار/بدهکار/پیش‌پرداخت به‌طور جداگانه از تسویه نقدی جدید نگهداری می‌شوند.

ابزار `match_to_existing_payment` وجه نقد ثبت‌شده در همان بانک/ارز/مبلغ/جهت را پیوند می‌دهد و transactionId/paymentId/journalEntryId را بازمی‌گرداند. این ابزار از نرخ تسعیر ارز ذخیره‌شده بدون استعلام جاری یا ثبت مجدد استفاده می‌کند؛ حامل‌های غیرنقدی با خطا مواجه می‌شوند.
ابزار `match_to_existing_journal` یک سند حسابداری ثبت‌شده، برگشت‌نخورده و متعلق به خود را که گردش خالص بانکی آن دقیقاً با سطر مطابقت دارد پیوند می‌دهد و transactionId/matchType/journalEntryId را برمی‌گرداند. تطبیق مستقیم سند از نرخ تسعیر عینی ارز مبنا (base-currency identity FX) پشتیبانی می‌کند؛ وجوه نقد ارزی از تطبیق پرداخت موجود استفاده می‌کنند. ابزار `get_bank_invoice_matches` پیشنهادهای فاکتور با ارز یکسان و فاکتورهای باز را همراه با مبالغ عددی و نام‌های مستعار دقیق برحسب واحد فرعی بازمی‌گرداند.

تمام وجوه/مجموع‌ها باید در محدوده اعداد صحیح امن تا 9007199254740991 بگنجند؛ رشته‌های دقیق بزرگ‌تر به‌طور واضح خطا می‌دهند. مبالغ/تاریخ‌های موجود قابل بازنویسی نیستند. دوره‌های مالی بسته، سوابق قدیمی فاقد شرایط، مراجع خارجی و سطرهای پیوندشده/مستثنی‌شده با خطا مواجه می‌شوند. تطبیق‌های تکراری یا متناقض نمی‌توانند ثبت جدیدی ایجاد کنند. عملیات انتقال و واگرد/جلسه شرایط اعتبارسنجی جداگانه‌ای دارند.

## ابزارهای انتقال بانکی

ابزار `record_bank_transfer` وجوه را بین دو حساب بانکی/نقدی فعال متعلق به خود در همان ارز جابه‌جا می‌کند. مقادیر fromBankAccountId، toBankAccountId و تاریخ میلادی را ارائه دهید. مقدار عددی `amount` همچنان واحدهای فرعی صحیح ارز است (USD 1250 سنت = $12.50). مقادیر `amountMinor: "1250"` و واحد اصلی اعشاری `amountExact: "12.50"` نام‌های مستعار دقیق هستند؛ آن‌ها باید همخوانی داشته باشند. مبالغ و مجموع اسناد تبدیل‌شده باید در محدوده 9007199254740991 قرار گیرند. این ابزار journalEntryId را بازمی‌گرداند و یک سند حسابداری، دو گردش جفت‌شده علامت‌دار و لاگ حسابرسی را به‌صورت اتمیک (atomic) ذخیره می‌کند. هر فراخوانی یک انتقال جدید ایجاد می‌کند؛ کلید تکرار وجود ندارد.

ابزار `match_transfer` مقادیر transactionId و targetBankAccountId را به همراه counterTransactionId اختیاری دریافت می‌کند. این ابزار از مبلغ ذخیره‌شده صورت‌حساب استفاده می‌کند؛ تراکنش مقابل باید پیوندنیافته، تسویه‌نشده، برابر و در جهت مخالف با همان ارز باشد. حذف/null بودن آن، یک تراکنش آینه‌ای ایجاد می‌کند. این ابزار transactionId، journalEntryId، counterTransactionId و mirrorCreated را بازمی‌گرداند. تطبیق‌های تکراری/متناقض به‌جای ثبت مجدد، رد می‌شوند. هر دو تاریخ باید در دوره باز باشند. هر دو ابزار به manage:banking نیاز دارند، از نرخ تسعیر ارز دقیق تاریخی استفاده می‌کنند و مانده‌های ذخیره‌شده/درجریان صورت‌حساب را حفظ می‌کنند. شرایط اعتبارسنجی واگرد/جلسه جداگانه باقی می‌ماند.

## عیب‌یابی

### «دسترسی به MCP نیازمند طرح Pro است»
سازمان شما از طرح رایگان استفاده می‌کند. برای فعال‌سازی دسترسی به MCP، از مسیر **تنظیمات > صورت‌حساب** (Settings > Billing) طرح خود را ارتقا دهید.

### «توکن دسترسی نامعتبر است»
توکن دسترسی شما منقضی شده است. کلاینت‌های MCP باید به‌طور خودکار با استفاده از توکن بازنشانی (refresh token) اقدام به تمدید توکن کنند. در صورت تداوم مشکل، سرور MCP را قطع و مجدداً متصل کنید.

### «عضو این سازمان نیستید»
حساب کاربری شما از سازمان حذف شده است. از یک مدیر بخواهید شما را دوباره اضافه کند.

### ابزارهای مغایرت‌گیری صورت‌حساب

برای بررسی‌های صورت‌حساب از `list_bank_reconciliations`، `create_bank_reconciliation`،
`reconciliation_report`، `complete_bank_reconciliation`،
`post_bank_reconciliation_adjustment`، `reconcile_bank_transaction`،
`unreconcile_bank_transaction` و `exclude_bank_transaction` استفاده کنید.
مانده‌ها و تعدیلات از **واحدهای خرد ارز بانک** (سنت دلار) به‌صورت عدد صحیح علامت‌دار (signed integer) همراه با نام‌های مستعار رشته‌ای منطبق با استاندارد `*Minor` تا حداکثر قدر مطلق ۹۰۰۷۱۹۹۲۵۴۷۴۰۹۹۱ استفاده می‌کنند. عملیات ایجاد نیازمند تاریخ‌های میلادی معتبر با احتساب هر دو سر بازه و مانده‌های افتتاحیه/اختتامیه است. گزارش شامل نام‌های مستعار دقیق، ارز بانک و ارز پایه دفتر کل (GL) است؛ مقایسه ارزهای ناهمسان امکان‌پذیر نیست و تکمیل/تعدیل نیازمند بانک‌هایی با ارز پایه است. تکمیل، هم گردش صورت‌حساب و هم سرجمع‌های دفتر کل را اثبات و تطبیق می‌دهد.

واگردانی (Undo)، اسناد روزنامه نقدی/دستی موجود را جدا می‌کند، ثبت‌های واجد شرایطِ ایجادشده توسط بانک را با استفاده از مبالغ/نرخ‌های ارز ذخیره‌شده معکوس می‌نماید، مانده‌های اسناد نقدی را بازیابی می‌کند، هر دو سر انتقال (transfer legs) را باطل می‌سازد، ردیف‌های ساختگی اثبات‌شده را حذف کرده و نشست‌های متأثر را مجدداً بازگشایی می‌کند. حامل‌های بستانکار/بدهکار/پیش‌پرداخت غیرنقدی را نمی‌توان به‌صورت نقدی باطل کرد. نتایج شامل reversalEntryId و deletedTransaction هستند؛ فیلد قدیمی voidedJournalEntryId ثبت جبران‌شده اولیه را مشخص می‌کند. به‌روزرسانی‌های امن وضعیت/حسابرسی به‌صورت اتمیک (atomic) اعمال می‌شوند. نیازمند manage:banking، تاریخ‌های باز، و علاوه بر آن manage:expenses برای واگردانی هزینه‌های بانکی است. تغییر وضعیت استثنا (Exclude toggles) و تعدیلات در هر فراخوانی رویدادهای جدیدی تلقی می‌شوند؛ سایر تغییر وضعیت‌های تکراری رد می‌شوند. قبل از تلاش مجددِ نامطمئن، وضعیت را بررسی کنید.

### ابزارهای پیکربندی حقوق و دستمزد

از `get_payroll_settings` و `update_payroll_settings` برای مقادیر پیش‌فرض متعلق به حقوق و دستمزد؛ از `list_payroll_deduction_types`، `get_payroll_deduction_type`، `create_payroll_deduction_type`، `update_payroll_deduction_type` و `delete_payroll_deduction_type` برای انواع کسورات؛ و از `list_payroll_employee_deductions`، `create_payroll_employee_deduction`، `update_payroll_employee_deduction` و `delete_payroll_employee_deduction` برای انتساب‌ها استفاده کنید. انتخاب‌های مالیاتی کارمند از `get_payroll_employee_tax_config` و `update_payroll_employee_tax_config` استفاده می‌کنند. این موارد نیازمند `manage:payroll` هستند.

پیکربندی مالیاتی نیازمند `manage:tax-config` است: `list_payroll_tax_brackets`، `get_payroll_tax_bracket`، `create_payroll_tax_bracket`، `update_payroll_tax_bracket`، `delete_payroll_tax_bracket` و توابع متناظر `list_payroll_tax_allowances`، `get_payroll_tax_allowance`، `create_payroll_tax_allowance`، `update_payroll_tax_allowance`، `delete_payroll_tax_allowance`.

مبالغ پولی به‌صورت سنت عدد صحیح غیرمنفی با نام‌های مستعار رشته‌ای منطبق با استاندارد `Minor` تا حداکثر ۹۰۰۷۱۹۹۲۵۴۷۴۰۹۹۱ باقی می‌مانند. فیلدهای آستانه/طبقه مالیاتی/معافیت سالانه به‌صورت سالانه باقی می‌مانند؛ بازنویسی‌های کسورات و کسر مالیات مضاعف به‌صورت دوره‌ای محاسبه می‌شوند. نرخ‌ها برحسب نقاط پایه (basis points)، درصدهای کسورات به‌صورت درصد اعشاری با قابلیت ذخیره‌سازی دقیق در binary32، شمارنده‌ها به‌صورت int32، و تاریخ‌ها به‌صورت میلادی YYYY-MM-DD هستند. ابزارها پوشش (envelope) داده/موجودیت سازگار با REST را برمی‌گردانند. عملیات نوشتن و حسابرسی به‌صورت اتمیک ثبت می‌شوند؛ ارجاعات کارمند/نوع/حساب باید متعلق به سازمان باشند. موارد تکراری معافیت کد ۴۰۹ بازمی‌گردانند؛ تاریخچه حذف نرم (soft-deleted) حفظ می‌شود. عملیات‌های پیکربندی حقوق و دستمزد را ثبت نهایی (post) نمی‌کنند و قواعد قانونی یا انتخاب حوزه قضایی را تأیید نمی‌نمایند.

### ابزارهای زمان‌بندی، مرخصی و نوبت کاری حقوق و دستمزد

از `list_payroll_timesheets`، `create_payroll_timesheet`، `get_payroll_timesheet`، `update_payroll_timesheet`، `list_payroll_timesheet_entries`، `create_payroll_timesheet_entry`، `delete_payroll_timesheet_entry` و `submit_payroll_timesheet` همراه با دسترسی `manage:timesheets` استفاده کنید. `approve_payroll_timesheet` و `reject_payroll_timesheet` نیازمند `approve:payroll` هستند. ورودی‌ها متعلق به تایم‌شیت پیش‌نویس مشخص‌شده هستند و ارجاعات پروژه باید متعلق به سازمان باشند.

`list_payroll_shifts`، `get_payroll_shift`، `create_payroll_shift`، `update_payroll_shift`، `delete_payroll_shift` نیازمند دسترسی `manage:shifts` هستند. `list_payroll_employee_schedules` و `create_payroll_employee_schedule` به `manage:payroll` و ارجاعات متعلق به کارمند/نوبت کاری فعال نیاز دارند.

از `list_payroll_leave_policies`، `get_payroll_leave_policy`، `create_payroll_leave_policy`، `update_payroll_leave_policy`، `list_payroll_leave_requests`، `get_payroll_leave_request`، `create_payroll_leave_request`، `update_payroll_leave_request` و `get_employee_leave_balances` همراه با `manage:leave` استفاده کنید. `approve_payroll_leave_request` و `reject_payroll_leave_request` نیازمند `approve:payroll` هستند. تأیید، ساعت‌ها را یک بار از یک مانده کافی برای سال میلادیِ درخواست کسر می‌کند؛ مانده‌های مفقود، تکراری یا ناکافی رد می‌شوند. ویرایش‌های عمومی درخواست فقط از دلایل در انتظار بررسی/لغو پشتیبانی می‌کنند.

`list_self_payroll_timesheets`، `create_self_payroll_timesheet`، `create_self_payroll_leave_request` و `get_self_payroll_leave_balances` نیازمند `self-service:payroll` هستند و یک کارمند فعال را از طریق عضویت احراز هویت‌شده تعیین می‌کنند؛ بازنویسی کارمند رد می‌شود. ساعت‌ها و درصدهای اعشاری حق‌الزحمه اضافی (premium percentages) به‌صورت عددی باقی مانده و باید بدون تغییر در حافظه موجود binary32 ذخیره شوند (مقادیر ۷.۵ و ۰.۲۵ کار می‌کنند؛ ۰.۱ رد می‌شود). تاریخ‌ها از فرمت میلادی YYYY-MM-DD با نقاط پایانی مرتب‌شده استفاده می‌کنند؛ مرخصی‌ها را بر اساس سال تفکیک کنید. هیچ نام مستعار پولی `Minor` روی واحدهای فیزیکی وجود ندارد. عملیات نوشتن، سرجمع‌ها، مانده‌ها و حسابرسی‌ها اتمیک هستند. فهرست‌ها پوشش‌های داده/صفحه‌بندی نام‌گذاری‌شده را برمی‌گردانند؛ متد موجود `get_employee_leave_balances` پروژکشن `balances` خود را حفظ می‌کند. ایجادها/افزودن‌ها رویدادهای مجزا هستند؛ قبل از تلاش‌های مجدد نامطمئن وضعیت را بررسی کنید. این عملیات حقوق و دستمزد را ثبت نهایی (post) نمی‌کنند و قوانین قانونی را تأیید نمی‌نمایند.

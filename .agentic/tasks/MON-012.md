# MON-012 — Roll out exact API and MCP boundary contracts

## Objective and implementation scope

Adopt MON-011 primitives at real REST/MCP money/rate request and response boundaries. Add explicit exact representations alongside supported v1 fields, or an explicitly versioned exact operation where numeric coexistence cannot represent a value. Audit direct NextResponse/JSON call sites and keep tool descriptions/schema expectations synchronized. Preserve org/role/period-lock/audit policy and validate before mutations. Coordinate with MON-007/008: do not advertise large-value posting while number domain consumers/ORM remain. Split further by verified domains if needed; retain parent integration criteria.

## Inputs

Parent [MON-006](MON-006.md), [source migration](../sources/SOURCE.md#database-and-currency-migration), [API compatibility](../sources/SOURCE.md#api-backward-compatibility), ADR-002/004 and MON-004 evidence.

## Acceptance criteria

- [ ] Inventory of money/rate REST and MCP endpoints identifies each adopted contract and any explicitly unsupported business range.
- [ ] Old supported numeric requests/responses and new exact-string clients pass real endpoint/tool fixtures, including authorization and organization isolation.
- [ ] Unsupported legacy requests fail before writes; no bigint serialization crash or silent numeric/unit loss at adopted boundaries.

## Verification

Run positive/negative contract fixtures, typecheck and lint. Record actual results and limits in new attempt evidence. No builds or unrequested dev server.

Not started.

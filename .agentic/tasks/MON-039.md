# MON-039 - Adopt exact invoice CRUD write contracts

## Objective and implementation scope

REST invoice create/patch/delete and MCP create/update/delete parity. Decimal-major prices differ from stored minor units. Preserve verified rounding/default/price-list/credit-limit/approval behavior, add exact aliases and validate all references, sums, products and old/new locks before atomic writes.

## Inputs

Parent [MON-019](MON-019.md), MON-011 evidence, ADR-006, MONEY_MANIFEST and actual source. Requirements: [migration](../sources/SOURCE.md#database-and-currency-migration) and [API compatibility](../sources/SOURCE.md#api-backward-compatibility).

## Acceptance criteria

- [x] Every boundary in this slice has documented inputs, outputs, units, exact aliases and supported ranges.
- [x] Actual REST/MCP fixtures cover legacy and exact clients, authorization and organization isolation.
- [x] Invalid or unsupported values fail before mutation; responses preserve numeric compatibility without bigint crashes or silent precision/unit loss.

## Verification

Run meaningful operation fixtures, typecheck and lint. No builds or unrequested dev server.

## Handoff

Implemented in shared `lib/api/invoice-writes.ts` / `invoice-write-wire.ts` and
adopted by REST POST/PATCH/DELETE plus MCP create/new-update/new-delete.
Exact decimal-major/integer-minor price aliases, safe bigint ratios/sums,
scoped dimensions/pricing/credit limits, old/new issue-date locks and atomic
number/header/line/create-approval mutation are qualified by real handlers/SDK
on migrated disposable PostgreSQL. Unit/typecheck/lint and inventory checks pass.
See `../registries/INVOICE_WRITE_WIRE_CONTRACTS.md` and attempt/review evidence.
No schema, configured app database, rollout flag, dev/build or deployment change.
Full-int64 mode, HTTP/session/OAuth/browser, external-writer/lock/workflow races
and posting/inventory/approval lifecycle remain their assigned gates.

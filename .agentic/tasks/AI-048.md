# AI-048 - Expand trusted previews to finite payment deletion and sending adapters

## Objective and implementation scope

Build on AI-047 business-policy observation and AI-045 proposal storage without
enabling sensitive dispatch. AI-046 independently integrates both children;
AI-043/044 remain decision/execution gates.

## Inputs

[AI-046](AI-046.md), [AI-047](AI-047.md), [preview contract](../docs/AI_ACTION_PREVIEWS.md),
[batch contract](../docs/AI_ACTION_BATCHES.md), actual settlement/deletion/email services.

## Acceptance criteria

- [x] Document a finite supported payment/deletion/external-sending set with exact strict arguments and current permissions from shared domain operations; reject unsupported variants, Stripe and credential/security/provider/role actions.
- [x] Supply complete domain-derived structured target, before/after, exact separate currency amounts, dates/FX, recipients and irreversible effects; preflight never mutates business data, lazily creates accounts or delivers externally.
- [x] Integrate every supported adapter with persisted versioned proposals, current business-policy evaluation, explicit dependency closure/selection, safe revision, stale detection, disclosure and retention; historical approval metadata never approves revised resources or self-approval.
- [x] Verify actual REST/MCP/disposable SQL for each action, financial/currency/reference/period gates, scope, stale resource/policy, unsafe recipients, display bounds and no effects; run static/schema/capability/coverage/controller checks.

## Verification

Focused actual REST/MCP/disposable-loopback SQL checks, typecheck/lint, generated
migrations if schema changes, capability/coverage/controller/diff checks. No build,
dev server, provider qualification or sensitive-dispatch activation.

## Handoff

Implemented finite observation-only single invoice/bill settlements, qualified
manual draft deletion and saved-contact invoice-summary email. Shared domain
preflight takes read-only snapshots, requires existing ledger setup, derives
exact separate currency amounts/content/recipients and never calls effects.
Added three REST/MCP observations and integrated all adapters with existing
versioned proposals, current business policy, per-action live grants, dependency
closure/selection, fixed-expiry revision, stale detection and generic retention.
Historical approvals never authorize revised resources or self-approval.

Actual REST/MCP/disposable SQL and existing journal/proposal/runtime/domain
regressions pass (11 integration suites), plus 26 focused unit checks, typecheck,
lint, schema drift, capability/coverage, legacy money and controller/diff checks.
Full lint retains 20 existing warnings; money inventory retains exactly its 1447
baseline errors, with no new failures after scoped consumer refresh. See
[attempt](../evidence/AI-048-attempt-1.md), [self-review](../evidence/AI-048-review-1.md)
and [finite contract](../docs/AI_FINITE_ACTION_ADAPTERS.md) for exact limits.

Next is AI-046 combined integration; AI-042/008 remain open parents and AI-043/044
retain decisions/fenced dispatch. Ordinary model catalog stays seven read/draft
tools. No schema migration, sensitive execution, real delivery/provider call,

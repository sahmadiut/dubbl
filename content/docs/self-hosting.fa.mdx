## Docker Compose

ساده‌ترین روش برای میزبانی شخصی Dubbl استفاده از Docker Compose است.

```yaml title="docker-compose.yml"
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgresql://dubbl:dubbl@db:5432/dubbl
      AUTH_SECRET: change-me-in-production
      AUTH_URL: https://your-domain.com
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: dubbl
      POSTGRES_PASSWORD: dubbl
      POSTGRES_DB: dubbl
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

## استقرار در محیط پروداکشن

<Steps>
  <Step>
    ### ساخت و راه‌اندازی

    ```bash
    docker compose up -d
    ```
  </Step>
  <Step>
    ### اعمال اسکیما در پایگاه داده

    ```bash
    docker compose exec app pnpm db:push
    ```
  </Step>
  <Step>
    ### بارگذاری داده‌های نمونه اولیه (اختیاری)

    ```bash
    docker compose exec app pnpm db:seed
    ```
  </Step>
</Steps>

## متغیرهای محیطی

| متغیر | الزامی | توضیحات |
|----------|----------|-------------|
| `DATABASE_URL` | بله | رشته اتصال PostgreSQL |
| `AUTH_SECRET` | بله | کلید امنیتی تصادفی برای امضای JWT |
| `NEXT_PUBLIC_APP_URL` | بله | نشانی URL عمومی نمونه شما |
| `AUTH_GOOGLE_ID` | خیر | شناسه کلاینت Google OAuth |
| `AUTH_GOOGLE_SECRET` | خیر | کلید محرمانه کلاینت Google OAuth |
| `AUTH_APPLE_ID` | خیر | شناسه سرویس Apple Sign In |
| `AUTH_APPLE_TEAM_ID` | خیر | شناسه تیم Apple Developer |
| `AUTH_APPLE_KEY_ID` | خیر | شناسه کلید Apple Sign In |
| `AUTH_APPLE_KEY_BASE64` | خیر | کلید خصوصی ‎.p8 با فرمت Base64 |
| `STRIPE_SECRET_KEY` | خیر | کلید Stripe API برای صورت‌حساب |
| `STRIPE_WEBHOOK_SECRET` | خیر | کلید محرمانه امضای وب‌هوک Stripe |
| `RESEND_API_KEY` | خیر | کلید Resend API برای ارسال ایمیل‌های پلتفرم |
| `TRIGGER_PROJECT_REF` | بله | شناسه مرجع پروژه Trigger.dev برای وظایف پس‌زمینه در پروداکشن |
| `TRIGGER_SECRET_KEY` | بله | کلید محرمانه Trigger.dev برای وظایف زمان‌بندی‌شده و تلاش‌های مجدد با تاخیر |
| `S3_BUCKET` | خیر | باکت S3 برای آپلود فایل‌ها |
| `S3_REGION` | خیر | منطقه (Region) مربوط به S3 |
| `S3_ACCESS_KEY_ID` | خیر | شناسه کلید دسترسی S3 |
| `S3_SECRET_ACCESS_KEY` | خیر | کلید دسترسی محرمانه S3 |
| `S3_ENDPOINT` | خیر | اندپوینت سفارشی S3 (برای MinIO و غیره) |

<Callout type="warn">
  در محیط پروداکشن همیشه یک مقدار قوی و منحصربه‌فرد برای `AUTH_SECRET` تعیین کنید. می‌توانید با دستور `openssl rand -base64 32` آن را ایجاد کنید.
</Callout>

## احراز هویت

سامانه Dubbl از سه روش احراز هویت پشتیبانی می‌کند:

- **ایمیل و رمز عبور** - به‌صورت پیش‌فرض و بدون نیاز به پیکربندی اضافه کار می‌کند
- **ورود با گوگل (Google OAuth)** - نیازمند `AUTH_GOOGLE_ID` و `AUTH_GOOGLE_SECRET` از [Google Cloud Console](https://console.cloud.google.com/apis/credentials)
- **ورود با اپل (Apple Sign In)** - نیازمند `AUTH_APPLE_ID`، `AUTH_APPLE_TEAM_ID`، `AUTH_APPLE_KEY_ID` و `AUTH_APPLE_KEY_BASE64` از [Apple Developer](https://developer.apple.com). فایل کلید ‎`.p8` خود را با دستور `base64 -w0 AuthKey_XXXXXXXXXX.p8` انکود کنید

برای ارائه‌دهندگان OAuth، نشانی Callback URL را برابر با `https://your-domain.com/api/auth/callback/google` (یا `apple/`) قرار دهید.

## راه‌اندازی اولین کاربر

نخستین کاربری که در یک نمونه (اینستنس) جدید ثبت‌نام می‌کند، به‌طور خودکار **مدیر ارشد سایت** می‌شود. این موضوع هم در ثبت‌نام با ایمیل/رمز عبور و هم از طریق OAuth صدق می‌کند. مدیران ارشد سایت می‌توانند به پنل مدیریت در مسیر `/admin` دسترسی داشته باشند و تنظیمات سراسری سایت را در `/admin/settings` پیکربندی کنند.

## کنترل‌های ثبت‌نام

کنترل کنید چه کسانی می‌توانند روی نمونه‌ی شما حساب کاربری ایجاد کنند:

| حالت | توضیحات |
|------|---------|
| `open` | هر کسی می‌تواند ثبت‌نام کند (پیش‌فرض) |
| `invite_only` | تنها کاربرانی که دعوت‌نامه دارند می‌توانند ثبت‌نام کنند |
| `disabled` | عدم امکان ثبت‌نام جدید (به‌جز اولین کاربر) |

از طریق متغیر محیطی (`REGISTRATION_MODE`) یا صفحه‌ی تنظیمات مدیریت در `/admin/settings` قابل تنظیم است.

## محدودیت‌های دامنه

با تنظیم `ALLOWED_EMAIL_DOMAINS` (جداشده با کاما) یا پیکربندی آن در تنظیمات مدیریت، ثبت‌نام را به دامنه‌های ایمیل خاصی محدود کنید. پس از تنظیم، تنها کاربرانی با دامنه‌های ایمیل منطبق می‌توانند ثبت‌نام کرده یا از طریق OAuth وارد شوند.

```bash
ALLOWED_EMAIL_DOMAINS="acme.com,example.com"
```

## حالت نامحدود خودمیزبانی‌شده

بدون پیکربندی Stripe، همه‌ی سازمان‌ها به‌طور خودکار تمام قابلیت‌های نامحدود پلن Pro را دریافت می‌کنند. هیچ صورت‌حساب، اشتراک یا محدودیت پلنی اعمال نمی‌شود. این وضعیت به‌طور خودکار بر اساس نبودِ `STRIPE_SECRET_KEY` شناسایی می‌شود.

شما همچنین می‌توانید این رفتار را از صفحه‌ی تنظیمات مدیریت کنترل کنید:
- **خودکار (Auto)** (پیش‌فرض) - نامحدود در صورت عدم پیکربندی Stripe
- **همیشه روشن (Always on)** - فعال‌سازی اجباری حالت نامحدود صرف‌نظر از پیکربندی Stripe
- **همیشه خاموش (Always off)** - اعمال محدودیت‌های پلن حتی بدون پیکربندی Stripe

## تنظیمات مدیریت

مدیران ارشد سایت می‌توانند تمام تنظیمات خودمیزبانی را از `/admin/settings` پیکربندی کنند:
- حالت ثبت‌نام و دامنه‌های مجاز ایمیل
- مجوزهای ایجاد سازمان
- کلید فعال/غیرفعال‌سازی حالت نامحدود خودمیزبانی‌شده

## صورت‌حساب (Stripe)

صورت‌حساب کاملاً اختیاری است. بدون پیکربندی Stripe، همه‌ی کاربران به‌طور خودکار از قابلیت‌های نامحدود پلن Pro بهره‌مند می‌شوند. مدیران ارشد سایت همچنین می‌توانند محدودیت‌های پلن را به‌ازای هر سازمان از مسیر `/admin/organizations` لغو (override) کنند.

برای فعال‌سازی پلن‌های پولی، راهنمای [راه‌اندازی صورت‌حساب و Stripe](/docs/settings/billing) را برای دستورالعمل‌های کامل پیرامون ایجاد محصولات، قیمت‌ها و پیکربندی وب‌هوک‌ها مطالعه کنید.

<Callout type="info">
  نمونه‌های خودمیزبانی‌شده نیازی به Stripe ندارند. تمام قابلیت‌ها به‌طور خودکار آنلاک هستند.
</Callout>

## ایمیل

ایمیل‌های سطح پلتفرم (خوش‌آمدگویی، دعوت‌نامه‌ها، هشدارهای ورود، خلاصه‌ی اعلان‌ها) از [Resend](https://resend.com) استفاده می‌کنند. برای فعال‌سازی این موارد، `RESEND_API_KEY` را تنظیم کنید. بدون آن، ارسال ایمیل‌های پلتفرم بدون نمایش خطا نادیده گرفته می‌شود.

ایمیل‌های سطح سازمان (فاکتورها، یادآوری‌ها، صورت‌حساب‌ها) از پیکربندی SMTP اختصاصی هر سازمان که در Settings > Email تنظیم می‌شود، استفاده می‌کنند.

## وظایف پس‌زمینه (Background Jobs)

دابل برای نگهداری‌های زمان‌بندی‌شده و تلاش‌های مجدد تاخیردار از Trigger.dev استفاده می‌کند. پیش از دریافت ترافیک، `TRIGGER_PROJECT_REF` و `TRIGGER_SECRET_KEY` را در محیط پروداکشن تنظیم کنید.

وظایف زمان‌بندی‌شده در `trigger/scheduled.ts` تعریف شده‌اند:

- خلاصه‌ی اعلان‌ها هر ۱۵ دقیقه
- زمان‌بندی گزارش‌ها به‌صورت ساعتی
- تلاش مجدد Stripe به‌صورت ساعتی
- صدور فاکتور، دفترداری، پاک‌سازی زباله‌دان و پشتیبان‌گیری به‌صورت روزانه

شکست در تحویل وب‌هوک، تلاش‌های مجدد را با تأخیر مشخص زمان‌بندی می‌کند، بنابراین تلاش‌های مجدد در زمان عقب‌نشینی (backoff) مورد نظر بدون نیاز به polling انجام می‌شوند. در صورتی که هنگام شکست تحویل وب‌هوک، `TRIGGER_SECRET_KEY` وجود نداشته باشد، آن اجرای تلاش مجدد نمی‌تواند زمان‌بندی شود.

برای توسعه‌ی محلی:

```bash
pnpm trigger:dev
```

برای محیط پروداکشن، وظایف Trigger.dev را دیپلوی کنید:

```bash
pnpm trigger:deploy
```

## پایگاه داده

دابل از PostgreSQL استفاده می‌کند. حداقل نسخه: **15**.

اسکیما توسط Drizzle ORM مدیریت می‌شود. برای اعمال تغییرات اسکیما:

```bash
pnpm db:push
```

## فضای ذخیره‌سازی

بارگذاری فایل‌ها (رسیدها، پیوست‌ها) نیازمند فضای ذخیره‌سازی سازگار با S3 است:

<Tabs items={["AWS S3", "MinIO", "Cloudflare R2"]}>
  <Tab value="AWS S3">
    فضای ذخیره‌سازی ابری استاندارد. `S3_ENDPOINT` را برابر با `https://s3.amazonaws.com` قرار دهید یا آن را خالی بگذارید.
  </Tab>
  <Tab value="MinIO">
    فضای ذخیره‌سازی خودمیزبان سازگار با S3. مقدار `S3_ENDPOINT` را روی نشانی سرور MinIO خود تنظیم کنید.
  </Tab>
  <Tab value="Cloudflare R2">
    جایگزینی مقرون‌به‌صرفه. مقدار `S3_ENDPOINT` را روی نشانی اندپوینت R2 خود قرار دهید.
  </Tab>
</Tabs>

<Callout type="info">
  بدون پیکربندی S3، قابلیت‌های بارگذاری فایل غیرفعال خواهند بود، اما سایر بخش‌های برنامه به‌صورت عادی کار می‌کنند.
</Callout>

## پشتیبان‌گیری

به‌طور منظم از پایگاه داده PostgreSQL خود نسخه پشتیبان تهیه کنید:

```bash
# استخراج پایگاه داده
docker compose exec db pg_dump -U dubbl dubbl > backup.sql

# بازیابی
docker compose exec -T db psql -U dubbl dubbl < backup.sql
```

<Callout type="warn">
  پشتیبان‌گیری‌های خودکار را زمان‌بندی کنید. از دست رفتن داده‌های مالی می‌تواند فاجعه‌بار باشد.
</Callout>

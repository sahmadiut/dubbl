# LOC-129 - Build localized currency labels and shared controls

## Objective and implementation scope

Provide a dependency-free language-aware currency-label adapter with owner-specified IRR name, Persian names for supported currencies, deterministic unknown-code fallback and unchanged English/reference values. Adopt it in CurrencySelect (compact, full, search, accessible labels and canonical callbacks), CurrencyInput unit prefixes, DualAmount including missing-rate labels and the explicit localized exact-money formatter. Keep arbitrary caller prefixes and canonical hidden values unchanged. No domain-wide adoption is claimed here.

## Inputs

- Parent [LOC-115](LOC-115.md), its full owner scope and acceptance criteria.
- Actual website source and existing exact-money/catalog contracts.

## Acceptance criteria

- [x] Shared adapter covers all supported currency codes, literal Persian IRR, deterministic fallback and preserved English/reference values independently of numerals.
- [x] Production shared picker/input/DualAmount and exact formatter adopt localized unit names with canonical callbacks, hidden fields and unchanged exact 0/2/3-place semantics.
- [x] Real bilingual provider/render/callback tests, typecheck, owned lint, catalog/money/controller/diff checks pass; remaining website adoption is explicitly assigned to LOC-130 through LOC-132.

## Verification

Use real PresentationProvider/next-intl production rendering. Record exact commands, fixtures, results and limits in task-specific evidence. Do not run full builds or dev server; no application DB writes. Preserve Stripe under DEC-008; no Stripe-specific adoption or dedicated work is authorized. No new operation or endpoint, so existing MCP canonical codes remain unchanged.

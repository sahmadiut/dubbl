# AI capability and gap matrix

AI-001 source baseline, 2026-10-27; implementation owner: Codex task_001. This is an inventory and dispatch contract, not an enabled agent. **Chat exposure is empty.** AI-006 must individually accept operations before adding them to the dispatcher. Existing MCP functionality stays intact.

## Reproducible operation inventory

`AI_CAPABILITIES.json` inventories all 104 modules actually imported and called by `lib/mcp/tools/index.ts`, 786 MCP names, 556 API route files (including public routes), and 208 UI pages. Each tool has its source module/line, description or source expression, directly observed permission guards, imported calls, and direct DB usage. Every operation is disabled for chat pending review. All route paths/methods and page paths remain listed, including surfaces with no corresponding MCP operation.

Run `node scripts/audit-ai-capabilities.mjs` to detect drift; after reviewing changed source, use `--write` to regenerate. It parses TypeScript syntax without importing application code, initializing a DB or invoking a tool. Unknown dynamic names and duplicate names fail the audit. Existing registration loops and the imported project operation table are expanded explicitly.

The inventory deliberately does **not** infer authorization, safe writes or shared-service parity from names, imports or descriptions. `directPermissions: []` means no direct literal guard was found, not that access is unrestricted: helpers can enforce additional permissions. `directImportedCalls` includes schemas/formatters/error wrappers as well as business functions. `directDatabase` identifies inline DB references, not their effects. Dynamic descriptions stay as source expressions. AI-006 must trace actual handlers and services, including indirect guards and side effects, and attach exact permissions, argument schema, result schema, approval class, idempotency/recovery behavior and REST parity tests to each enabled entry. The JSON is never a runtime allowlist.

## Explicit unsupported operations and gap owners

AI-005 adds the `ai-usage` administration/report module: price and budget
mutations/listings are excluded from ordinary chat through `AI_USAGE_ADMIN_TOOLS`.
Own usage and organization aggregate reporting have separate live permissions;
no transcript or internal settlement operation is exposed. AI-006 must enforce
these markers before any chat discovery/dispatch. Metering does not activate AI.

REST-only/site-only surfaces remain unsupported until individually mapped: authentication/sign-up/session revocation, invitation and invite-link flows, organization member/advisor/team administration, API-key lifecycle, email configuration, global search, own-user security/profile, platform-wide administration, binary upload transport and any nested action missing from the MCP inventory. Some related domains have MCP tools; a domain match never proves operation parity. AI-006 compares every route/method and page action, records supported/unsupported/deferred scope and adds bounded missing shared services/MCP operations. Site-only and security-sensitive routes are excluded from ordinary chat by default.

There are no arbitrary SQL/shell/browser tools, new external connectors, general web browsing, automatic scheduled agent runs, hosted-provider MCP delegation, newly deferred parity, new Iranian tax capabilities or Stripe work. DEC-010 Iran capabilities not yet implemented cannot be advertised as tools. Adding business coverage requires implementation plus its MCP operation and a reviewed entry; retaining existing runtime behavior requires no AI exposure.

First implementation slice for AI-006: search/read an invoice and prepare a validated draft through `list_invoices`/`get_invoice`/`create_invoice`, calling `lib/api/invoice-reads.ts`/`invoice-writes.ts`. Invoice write schema requires organization-owned references, explicit currencies and existing money aliases. Any prerequisite lookup (contacts/accounts/items) must first get its own reviewed shared service and MCP mapping; unsupported lookup is reported rather than guessed. No approval/post/payment/email is implied by draft creation. AI-002 live identity and AI-003/007 durability must pass before actual dispatch. No current operation is enabled by this proposed first slice.

Exact-money contract: preserve canonical `*Minor` signed-integer strings, legacy safe-number compatibility limits and aliases, explicit currency/amount currency, domain-specific stored-unit exceptions, exact FX direction/rate/provenance and historical snapshots. Integer cents examples mean USD cents, not a universal two-decimal assumption. Input amounts go through existing schemas/services; the model never calculates or posts ledger arithmetic. Counts, hundredth quantities, basis points and date-only Gregorian strings remain distinct. Render/display localization cannot change persisted values. References and transactions remain organization-scoped, locked, audited and subject to existing approvals/idempotency.

# RTL-008 - Harden module forms tables charts and mixed identifiers

## Objective and implementation scope

Audit and adopt shared bidi/typography controls across all non-frozen forms, tables, metadata identifiers, document IDs, IBANs, URLs, email, keys, grids/charts/tooltips, portal and output surfaces. Preserve canonical strings, exact money, native control contracts, saved/issued snapshots, machine exports and owner Stripe freeze. Review long translations, small widths, zoom/text-spacing resilience and accessible names/table headers/errors/totals with actual behavior/CSS evidence under DEC-005; retain genuinely required native/accounting/output qualification and independent RTL-002 combined acceptance. Split further bounded domain adoption only when justified by actual audit and maintain exhaustive ownership.

## Inputs

- Parent [RTL-002](RTL-002.md), [requirements](../sources/SOURCE.md#rtl-uiux-strategy) and prior RTL-001 evidence.
- Actual fork source and installed framework behavior. DEC-005 excludes screenshot requirements, not behavioral/layout/accessibility review. DEC-008 freezes Stripe/provider work.

## Acceptance criteria

- [ ] All assigned mixed identifiers have correct ordered/selectable isolation, with technical/output/provider exceptions and remaining qualification inventoried exhaustively.
- [ ] Forms, tables, grids, charts and tooltips are reviewed in both directions for long text, narrow widths, zoom/text spacing; genuine issues are repaired and exact evidence/limitations recorded.
- [ ] Accessible names, headers, errors, totals and canonical callbacks/output contracts pass meaningful bilingual regression checks, with RTL-002 independent acceptance retained.

## Verification

Use real controls/components, exact callback/value assertions, appropriate CSS/runtime checks and focused regressions. Record exact commands/results/context and limits. No full build/dev startup or application DB writes. Existing REST/MCP values remain canonical; no new operation is introduced.

## Handoff

Not started. This child does not complete parent RTL-002 or sibling acceptance.

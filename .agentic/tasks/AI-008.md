# AI-008 - Add action previews approvals and resumable execution

## Objective and implementation scope

Add risk-based confirmation without asking before every harmless step; integrate existing business approvals.

This task implements the owner-requested AI feature; it does not authorize deployment or relax existing financial/release gates.

## Inputs

- [Product experience contract](../docs/AI_PRODUCT_EXPERIENCE.md): normative journeys, UI states and observable UX acceptance.
- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Architecture and delivery plan](../docs/AI_AGENT_PLAN.md).
- Actual source and dependency evidence; verify current contracts before editing.

## Acceptance criteria

- [ ] Reads and permitted draft preparation proceed within policy. Supported posting, payments, deletion and external sending require explicit scoped approval consistent with existing domain policy; no blanket permission or ambiguous confirmation grants additional actions. Credential/security/provider/role configuration remains excluded from ordinary chat even if a model requests approval.
- [ ] Approval binds the actor, organization, exact action arguments, resource version and expiry; edits invalidate approval, and current permissions are checked at execution.
- [ ] Batch approval shows each proposed effect; cancellation, rejection, stale data, replay, double submission and partial failure do not duplicate operations or claim transaction-wide rollback.
- [ ] The assistant cannot approve its own actions or bypass accounting approvals; REST/MCP preview, approve and reject operations enforce the same rules.

- [ ] Return a structured business preview suitable for AI-027: action-specific label, target reference, before/after values, exact amounts with currency, recipients, irreversible effects, existing business-approval status, expiry and version. Never return raw tool JSON as the only user explanation.
- [ ] Expose shared REST/MCP operations to retrieve/revise previews and submit explicit approvals/rejections. Bind selected batch items and dependencies exactly; changing selection or arguments regenerates the preview, and dependent actions cannot proceed after a prerequisite is rejected.
- [ ] Return localized-safe stale/expired/denied/error codes and permitted recovery actions; clarify who must act when the current user cannot approve without disclosing unauthorized identities or records. Approval requirements cannot be satisfied by clarification text, a model-generated yes, or a hidden policy change.

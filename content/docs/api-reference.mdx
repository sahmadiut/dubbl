Dubbl provides a full REST API for programmatic access to all features.

## Authentication

<Tabs items={["API Key (Recommended)", "Session Cookie"]}>
  <Tab value="API Key (Recommended)">
    Create API keys in **Settings > API Keys**, then include in requests:

    ```bash
    curl -H "Authorization: Bearer your-api-key" \
         -H "x-organization-id: org-id" \
         https://your-instance.com/api/v1/contacts
    ```
  </Tab>
  <Tab value="Session Cookie">
    Automatically included when making requests from the Dubbl web app. No additional setup needed.
  </Tab>
</Tabs>

## Exchange rate inputs

`POST /api/v1/exchange-rates` accepts a batch of manual rates. Exact clients can
send a decimal string in `rateExact`:

```json
{
  "rates": [
    {
      "baseCurrency": "USD",
      "targetCurrency": "EUR",
      "date": "2026-10-02",
      "rateExact": "0.9",
      "rateDirection": "quote_per_base"
    }
  ]
}
```

This synthetic example means 0.9 EUR per 1 USD. The existing numeric `rate` input
remains integer millionths: `900000` represents the same quote. If both fields
are supplied, they must agree. `PUT /api/v1/exchange-rates/{id}` accepts either
alias too. Responses preserve numeric `rate` and return the normalized string
`rateExact`, direction and storage/provenance metadata.

During legacy coexistence, saved rates must fit 0.000001 through 2147.483647 with
at most six decimal places. A valid exact string outside that range returns HTTP
422 with `code: "LEGACY_NUMERIC_RANGE"` before writing any rate in the batch.
Invalid or conflicting aliases return 400. Same-currency quotes must equal 1.
Writes require `manage:tax-config` permission and operate within the authenticated
organization. Dates are Gregorian `YYYY-MM-DD`.

The MCP `set_exchange_rate` tool accepts `rateExact` too. Its original numeric
field, `rateDecimal`, is **unscaled** (0.9 in this example), unlike REST `rate`.
MCP historical inverse lookups return a string rounded to 18 decimal places
alongside a legacy numeric rate rounded to six places. The `convert_amount`
tool remains a legacy numeric preview for currencies with matching minor-unit
scales and safe intermediate products; full-range amount strings and mixed-scale
conversion are not available in that operation yet.

## Contact credit limits and balances

`POST /api/v1/contacts` and `PATCH /api/v1/contacts/{id}` accept an optional
`creditLimitMinor` canonical integer string alongside the numeric `creditLimit`:

```json
{"creditLimitMinor": "1250"}
```

This means the existing stored integer 1250 (USD cents for a USD contact).
Neither alias rescales history for another currency. Both fields must agree if
supplied together; `null` clears the limit, zero sets a zero limit, and omission
keeps the current limit on updates. Responses include numeric `creditLimit` and
nullable string `creditLimitMinor`. The MCP `create_contact` and `update_contact`
tools accept the same aliases; `list_contacts` and `get_contact` return them.

Current supported write range is 0 through 9007199254740991. Valid int64 strings
above this range return HTTP 422 with `code: "LEGACY_NUMERIC_RANGE"` before writes.
Malformed, negative or conflicting aliases return 400. Writes require
`manage:contacts`; existing organization and resource/currency-plan checks apply.

REST contact listings additionally return `owesYouMinor`, `youOweMinor` and
`overdueMinor` alongside their numeric fields. Sums are calculated exactly and
must fit the safe numeric range; numeric fields keep their existing cents units.
Nonzero outstanding documents must use the contact's currency. A page containing
incompatible currencies or unsafe totals returns 422 rather than combining
unlike currencies or rounding amounts. MCP contact listings retain their existing
shape without these balance aggregates. Full int64 business operations and
currency-grouped contact balance reporting are pending further rollout.

## Budget amount inputs

Budget POST/PATCH requests accept string aliases for signed integer cents:

```json
{
  "lines": [{
    "accountId": "your-account-uuid",
    "totalMinor": "1250",
    "periods": [{
      "label": "January",
      "startDate": "2026-01-01",
      "endDate": "2026-01-31",
      "amountMinor": "1250"
    }]
  }]
}
```

Supply the usual budget header fields on creation. Numeric `total`/`amount`
remain supported and must agree with their string aliases when both are present.
Amounts retain the existing cents units; no currency rescaling occurs. Missing
period amounts default to zero. An explicit line total keeps precedence over
period sums; otherwise the sum becomes the total. Omitted/empty periods generate
from the effective header dates/type and distribute the total exactly, including
negative amounts. Dates are valid Gregorian date-only values with UTC boundaries.

Supported amounts and per-line period sums are -9007199254740991 through
9007199254740991, with at most 500 lines and 10000 periods per budget. Valid int64
strings outside the supported amount range return 422 (`LEGACY_NUMERIC_RANGE`)
before writes; malformed/conflicting aliases return 400. Account/fiscal-year refs
must belong to the authenticated organization. Create and replacement writes are
transactional and require `manage:budgets`.

GET by ID returns numeric fields alongside `totalMinor`/`amountMinor`. Lists and
create/update responses keep their header-only envelopes. MCP budget CRUD tools
accept/return the same aliases. Budget-versus-actual reports and frontend amount
arithmetic are still awaiting exact-money rollout; CRUD support does not establish
full-range reporting or production IRR readiness.

### Journal Entries
| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/entries` | List entries |
| POST | `/api/v1/entries` | Create entry |
| GET | `/api/v1/entries/:id` | Get entry |
| PUT/PATCH | `/api/v1/entries/:id` | Replace a draft entry header and lines |
| DELETE | `/api/v1/entries/:id` | Delete a draft entry and its lines |
| POST | `/api/v1/entries/:id/post` | Post entry |
| POST | `/api/v1/entries/:id/void` | Void entry |
| POST | `/api/v1/entries/recode` | Reclassify scoped line dimensions |
| POST | `/api/v1/bulk/entries/preview` | Preview grouped journal imports |
| POST | `/api/v1/bulk/entries/import` | Import grouped journal entries |

Journal CRUD accepts line `debitAmountMinor` and `creditAmountMinor` canonical
nonnegative integer strings alongside legacy `debitAmount`/`creditAmount` minor-unit
numbers. Both aliases must agree; an omitted side defaults to zero. Values and
per-entry sums must fit the current safe-number workflow (at most 9007199254740991).
`rateExact` accepts saved quote-per-base decimal strings exactly representable in
positive int32 millionths; dual `exchangeRate` must agree. Amount/rate range
failures return 422 with `LEGACY_NUMERIC_RANGE`, before writes.

REST detail retains historical fixed-two-decimal `debitAmount`/`creditAmount`
strings and adds raw `*Minor` strings plus saved exact FX metadata. REST list
retains its decimal-string `totalDebit` and adds `totalDebitMinor`. These aliases
never rescale stored values by currency. Automated entries can store already-base
amounts while the line currency tags the original document; reads do not apply FX
again. Mixed manual-currency list totals remain raw stored sums.

Creation requires `create:entries`; replacement/deletion requires `edit:entries`.
References must belong to the organization, and period locks/closed years apply.
Replacement/deletion is draft-only. MCP `list_entries`, `get_entry`, `create_entry`,
`update_entry` and `delete_entry` provide the corresponding operations, with
minor-unit numeric output plus exact aliases. REST create retains its existing
base-balance check for mixed currencies/rates, including per-line rounding slack
and safe FX-product limits; REST replacement and MCP create/update retain raw
debit/credit equality. These aliases do not enable full-int64 domain posting.
Post/void REST responses also include exact leg aliases and saved FX. Posting
requires `post:entries` and rechecks locks; void requires `void:entries` and writes
an atomic mirror without another FX conversion. Recode requires `edit:entries`,
scoped target dimensions and unlocked dates; `draftOnly=false` explicitly includes
posted entries. MCP lifecycle tools expose the corresponding header/count outputs.

REST bulk import/preview legacy `debit`/`credit` is fixed-two-decimal input:
`"12.50"` means 1250 stored units. MCP `import_journal_entries` and the new
`preview_journal_entries` retain integer cents: `1250` means 1250 units. Both accept
canonical `debitAmountMinor`/`creditAmountMinor` strings, with dual agreement and
safe-number value/group-sum limits. Prefer REST decimal strings; numeric decimal
input above `2^45 - 1` requires text or exact aliases. Extra fractional digits and
malformed inputs are rejected rather than rounded. Preview adds `totalDebitMinor`,
`totalCreditMinor` and `imbalanceMinor` strings. Imported legs retain legacy USD/
1:1 defaults; currency-aware decimal import is not introduced.

Import requires `manage:entries`, plus `post:entries` for `post=true`. Malformed
wire input fails before job creation. Business-invalid groups are reported in the
job; valid groups commit independently with atomic headers/legs. Sources are
quickbooks, xero, freshbooks, wave or custom, and grouped dates/memos/references
must agree. Full exact domain qualification remains separate work.

### Recurring Journals

| Method | Path | Description |
|--------|------|-------------|
| GET/POST | `/api/v1/recurring-journals` | List/create journal templates |
| GET/PATCH/DELETE | `/api/v1/recurring-journals/:id` | Read/edit/soft-delete a template |
| POST | `/api/v1/recurring-journals/:id/pause` | Toggle active/paused |
| POST | `/api/v1/recurring-journals/run` | Run this organization's due templates |

REST and MCP retain safe numeric **stored minor-unit** `debitAmount` and
`creditAmount` (USD cents), and add canonical `debitAmountMinor` and
`creditAmountMinor` strings on legs. Both input aliases must agree. Each leg has
one positive side; summed debits equal credits and must fit safe integers
(`<=9007199254740991`). Malformed/conflicting inputs fail validation; unsupported
numeric ranges return 422 `LEGACY_NUMERIC_RANGE` before mutation.

Saved `currencyCode` is retained on partial edits and posted verbatim without
rescaling. Templates have no configurable FX storage: rate aliases explicitly
represent fixed `exchangeRate:1000000`, `rateExact:"1"` and
`rateDirection:"quote_per_base"`. Nonidentity FX is rejected. This preserves the
existing template posting behavior, not currency-aware base conversion.

Dates are canonical Gregorian YYYY-MM-DD; startDate is immutable on edits.
Nullable endDate/maxOccurrences/reference/notes clear with null. Editing lines
fully replaces the balanced legs atomically. Writes require `manage:recurring`
and active organization-owned accounts/cost centers. Corresponding MCP tools are
`list_recurring_journals`, `get_recurring_journal`, `create_recurring_journal`,
`update_recurring_journal`, `set_recurring_journal_status`,
`pause_recurring_journal`, `delete_recurring_journal` and `run_recurring_journals`.

Generation validates retained amounts and dimensions, then commits each
**template's** entire catch-up and schedule together under a row lock. Concurrent
runs of that template do not duplicate entries. Locked/closed dates consume an
occurrence without posting; malformed templates fail without consuming their
schedule. Resume keeps nextRunDate and catches up. An earlier template can remain
committed if a later one fails; runs are not atomic across all templates.

### Public Payment Links and Customer Portal

These JSON routes use an existing bearer link token. Portal access is limited to
its contact and organization; revoked, expired or deleted-contact grants fail.
Existing numeric money fields retain their units and gain matching canonical
`*Minor` strings. For example, `total: 1250` also returns `totalMinor: "1250"`.
Amounts must fit the signed JavaScript safe-integer range; unsupported stored
amounts or sums return 422 with `LEGACY_NUMERIC_RANGE`.

| Method | Path | Money strings added |
|--------|------|--------------------|
| GET | `/api/pay/:token` | Pending invoice totalMinor, amountDueMinor; lines unitPriceMinor, amountMinor, taxAmountMinor |
| GET | `/api/portal/:token` | Contact and organization identity; no amounts |
| GET | `/api/portal/:token/invoices` | totalMinor, amountDueMinor |
| GET | `/api/v1/portal/:token/payments` | amountPaidMinor, totalMinor |
| GET | `/api/v1/portal/:token/quotes` | subtotalMinor, taxTotalMinor, totalMinor, billedTotalMinor; line money strings |
| GET | `/api/v1/portal/:token/statements` | amountMinor, paidMinor, balanceMinor, runningBalanceMinor; totalOutstandingMinor and currencyCode |
| POST | `/api/v1/portal/:token/quotes/:id/accept` | Updated quote with header money strings |
| POST | `/api/portal/:token/invoices/:id/approve` | Existing quote ID/status envelope; this historical route accepts a quote |

Acceptance requires a sent, unexpired, undeleted quote belonging to the token's
contact. Send no body or `{}`; amount/FX overrides and other fields are rejected.
Statement sums use exact integer arithmetic and reject mixed currencies. Existing
invoice selection and descending date order remain. Quantity is still hundredths
and discount percentages are basis points; monetary strings never rescale values.

MCP counterparts are `get_payment_link`, `get_portal_identity`,
`list_portal_invoices`, `list_portal_payments`, `list_portal_quotes`,
`get_portal_statement` and `accept_portal_quote`. All require the token to belong
to the authenticated organization. Reads require `view:data`; acceptance requires
`manage:invoices` and a `quoteId` UUID. Inputs are strict and accept no amounts.

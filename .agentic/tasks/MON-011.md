# MON-011 — Implement exact wire primitives and shared transport guards

## Objective and implementation scope

Implement canonical int64-string money and exact-decimal FX DTO/input primitives, explicit legacy/exact JSON serializers, shared REST response/MCP adapters and classified ORM compatibility errors. Preserve default v1 numeric types and units; fail visibly on unsafe/nonfinite numbers. Document the contract and pending endpoint adoption. This foundation does not claim direct NextResponse call sites, domain input schemas or full-range DB/business consumers have been migrated.

## Inputs

Parent [MON-006](MON-006.md), [source migration](../sources/SOURCE.md#database-and-currency-migration), [API compatibility](../sources/SOURCE.md#api-backward-compatibility), ADR-002/004 and MON-004 evidence.

## Acceptance criteria

- [x] Exact money/rate DTO and input fixtures preserve units, signed int64 limits and reject malformed/conflicting or unrepresentable legacy values.
- [x] Shared REST and MCP adapters serialize nested bigint without JSON crashes; default legacy mode preserves safe numeric clients and reports unsafe values with an explicit compatibility error.
- [x] Explicit exact-mode contract fixtures round-trip large signed values and tiny/high rates without Number coercion; adoption and deprecation limits are documented.

## Verification

Run positive/negative contract fixtures, typecheck and lint. Record actual results and limits in new attempt evidence. No builds or unrequested dev server.

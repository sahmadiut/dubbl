# Reviewed agent tool registry

AI-006 implements **seven operations**, not every site capability: contact list/detail,
journal list/detail, expense list/detail and new draft expense creation. The current
executable source of truth is `lib/ai/tool-catalog.ts`; exhaustive source/gap disposition
is [AI_TOOL_COVERAGE](../registries/AI_TOOL_COVERAGE.json), regenerated by
`node --import tsx scripts/audit-ai-tool-coverage.mjs --write` after the capability audit.
The earlier proposed invoice-first slice is superseded by this verified expense-draft
slice: it exercises an existing atomic shared service without posting, payment,
notification, stock, schedule or access effects. Invoice coverage remains AI-015.

All entries provide permission, strict input schema, shared MCP/service route,
money contract, schema version, resource-version behavior, effect, approval class,
result cap and retry contract. Only reads and the reviewed new draft are automatic.
No updates, deletions, posting, approval, payment, sharing, outbound communications,
credentials, pricing/budget/policy/security administration or arbitrary SQL/shell/code/URL
execution is model-dispatchable. Existing provider and usage administration deny sets
are tested against the allowlist. An object prototype key cannot address the registry.

Both organization and server-selected agent policies must explicitly enable each name;
missing/disabled policies return no tools. `manage:ai-policy` changes policies with CAS
and transactional content-free audit. Policy APIs and their MCP equivalents are
administration only and excluded from the chat catalog. Discovery uses live `use:ai`
plus each domain grant, not a cached role or a model-provided organization. Runtime must
choose the agent key from its trusted run configuration, never from proposed arguments.

`dispatchAgentTool` is an internal server function, not a generic REST/MCP execution
endpoint. It resolves the original credential, validates strict schemas (including all
nested expense lines), rechecks live actor and both policies immediately before dispatch,
and calls the **actual existing registered MCP tool** over an in-process linked transport;
there is no HTTP self-call. `wrapTool` revalidates identity again and shared services keep
their existing scope, period locks, plan/financial limits, approvals and initiating-user
audits. Expense creation creates only a new draft; existing claims and journals cannot
be edited or approved through this registry. Existing read services and money aliases
are retained; no tax, FX, mileage or ledger arithmetic is delegated to the model.

Unknown tools and invalid fields fail before dispatch. MCP `isError`, error payloads,
malformed envelopes and transport failures never become successful business actions.
Ambiguous writes are `uncertain`, with `never-automatically` retry; domain errors are
sanitized rather than returning raw inputs/errors to the model. Every output has an
explicit `untrusted` flag. Results larger than 32 KiB are omitted, retaining a created
expense UUID where available; this does not turn an already committed write into a
failure/retry. Dispatch audit stores only actor, organization and reviewed tool name.

AI-007 must bind this function to durable run/step IDs, global cancellation/kill switch,
deadlines, operation keys and reconciliation; it must not replay uncertain draft
creation. AI-008 owns sensitive preview/approval validation; no fabricated approval
argument can unlock a tool here. AI-013 must reconcile unresolved coverage and qualify
configured provider/runtime before any rollout. This task enables neither runtime nor
provider calls and changes no financial/IRR/release gate.

AI-018 inventory/pricing/procurement; AI-019 payroll/projects/CRM/planning;

reviewed shared-service mappings, split an oversized implementation, and retain

capabilities remain excluded under existing owner decisions. No claim of universal
site coverage follows from creation or completion of the registry task.

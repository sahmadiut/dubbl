# AI-048 - Expand trusted previews to finite payment deletion and sending adapters

## Objective and implementation scope

Build on AI-047 business-policy observation and AI-045 proposal storage without
enabling sensitive dispatch. AI-046 independently integrates both children;
AI-043/044 remain decision/execution gates.

## Inputs

[AI-046](AI-046.md), [AI-047](AI-047.md), [preview contract](../docs/AI_ACTION_PREVIEWS.md),
[batch contract](../docs/AI_ACTION_BATCHES.md), actual settlement/deletion/email services.

## Acceptance criteria

- [ ] Document a finite supported payment/deletion/external-sending set with exact strict arguments and current permissions from shared domain operations; reject unsupported variants, Stripe and credential/security/provider/role actions.
- [ ] Supply complete domain-derived structured target, before/after, exact separate currency amounts, dates/FX, recipients and irreversible effects; preflight never mutates business data, lazily creates accounts or delivers externally.
- [ ] Integrate every supported adapter with persisted versioned proposals, current business-policy evaluation, explicit dependency closure/selection, safe revision, stale detection, disclosure and retention; historical approval metadata never approves revised resources or self-approval.
- [ ] Verify actual REST/MCP/disposable SQL for each action, financial/currency/reference/period gates, scope, stale resource/policy, unsafe recipients, display bounds and no effects; run static/schema/capability/coverage/controller checks.

## Verification

Focused actual REST/MCP/disposable-loopback SQL checks, typecheck/lint, generated
migrations if schema changes, capability/coverage/controller/diff checks. No build,
dev server, provider qualification or sensitive-dispatch activation.

## Handoff

Not started. Shared settlement helpers currently combine preflight with locks and
lazy bank/FX-account creation; email rendering and delivery are separate but the
send schema permits display overrides. Extract/reuse domain preflight without
calling side-effect paths. Preserve existing direct domain contracts and Stripe.

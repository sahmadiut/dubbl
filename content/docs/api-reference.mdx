## Exchange rate inputs

`POST /api/v1/exchange-rates` accepts a batch of manual rates. Exact clients can
send a decimal string in `rateExact`:

```json
{
  "rates": [
    {
      "baseCurrency": "USD",
      "targetCurrency": "EUR",
      "date": "2026-10-02",
      "rateExact": "0.9",
      "rateDirection": "quote_per_base"
    }
  ]
}
```

This synthetic example means 0.9 EUR per 1 USD. The existing numeric `rate` input
remains integer millionths: `900000` represents the same quote. If both fields
are supplied, they must agree. `PUT /api/v1/exchange-rates/{id}` accepts either
alias too. Responses preserve numeric `rate` and return the normalized string
`rateExact`, direction and storage/provenance metadata.

During legacy coexistence, saved rates must fit 0.000001 through 2147.483647 with
at most six decimal places. A valid exact string outside that range returns HTTP
422 with `code: "LEGACY_NUMERIC_RANGE"` before writing any rate in the batch.
Invalid or conflicting aliases return 400. Same-currency quotes must equal 1.
Writes require `manage:tax-config` permission and operate within the authenticated
organization. Dates are Gregorian `YYYY-MM-DD`.

The MCP `set_exchange_rate` tool accepts `rateExact` too. Its original numeric
field, `rateDecimal`, is **unscaled** (0.9 in this example), unlike REST `rate`.
MCP historical inverse lookups return a string rounded to 18 decimal places
alongside a legacy numeric rate rounded to six places. The `convert_amount`
tool remains a legacy numeric preview for currencies with matching minor-unit
scales and safe intermediate products; full-range amount strings and mixed-scale
conversion are not available in that operation yet.

## Contact credit limits and balances

`POST /api/v1/contacts` and `PATCH /api/v1/contacts/{id}` accept an optional
`creditLimitMinor` canonical integer string alongside the numeric `creditLimit`:

```json
{"creditLimitMinor": "1250"}
```

This means the existing stored integer 1250 (USD cents for a USD contact).
Neither alias rescales history for another currency. Both fields must agree if
supplied together; `null` clears the limit, zero sets a zero limit, and omission
keeps the current limit on updates. Responses include numeric `creditLimit` and
nullable string `creditLimitMinor`. The MCP `create_contact` and `update_contact`
tools accept the same aliases; `list_contacts` and `get_contact` return them.

Current supported write range is 0 through 9007199254740991. Valid int64 strings
above this range return HTTP 422 with `code: "LEGACY_NUMERIC_RANGE"` before writes.
Malformed, negative or conflicting aliases return 400. Writes require
`manage:contacts`; existing organization and resource/currency-plan checks apply.

REST contact listings additionally return `owesYouMinor`, `youOweMinor` and
`overdueMinor` alongside their numeric fields. Sums are calculated exactly and
must fit the safe numeric range; numeric fields keep their existing cents units.
Nonzero outstanding documents must use the contact's currency. A page containing
incompatible currencies or unsafe totals returns 422 rather than combining
unlike currencies or rounding amounts. MCP contact listings retain their existing
shape without these balance aggregates. Full int64 business operations and
currency-grouped contact balance reporting are pending further rollout.

## Budget amount inputs

Budget POST/PATCH requests accept string aliases for signed integer cents:

```json
{
  "lines": [{
    "accountId": "your-account-uuid",
    "totalMinor": "1250",
    "periods": [{
      "label": "January",
      "startDate": "2026-01-01",
      "endDate": "2026-01-31",
      "amountMinor": "1250"
    }]
  }]
}
```

Supply the usual budget header fields on creation. Numeric `total`/`amount`
remain supported and must agree with their string aliases when both are present.
Amounts retain the existing cents units; no currency rescaling occurs. Missing
period amounts default to zero. An explicit line total keeps precedence over
period sums; otherwise the sum becomes the total. Omitted/empty periods generate
from the effective header dates/type and distribute the total exactly, including
negative amounts. Dates are valid Gregorian date-only values with UTC boundaries.

Supported amounts and per-line period sums are -9007199254740991 through
9007199254740991, with at most 500 lines and 10000 periods per budget. Valid int64
strings outside the supported amount range return 422 (`LEGACY_NUMERIC_RANGE`)
before writes; malformed/conflicting aliases return 400. Account/fiscal-year refs
must belong to the authenticated organization. Create and replacement writes are
transactional and require `manage:budgets`.

GET by ID returns numeric fields alongside `totalMinor`/`amountMinor`. Lists and
create/update responses keep their header-only envelopes. MCP budget CRUD tools
accept/return the same aliases. Budget-versus-actual reports and frontend amount
arithmetic are still awaiting exact-money rollout; CRUD support does not establish
full-range reporting or production IRR readiness.

### Invoices
| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/invoices` | List invoices |
| GET | `/api/v1/invoices/summary` | Invoice totals and aging with exact minor-unit aliases |
| POST | `/api/v1/invoices` | Create invoice |
| GET | `/api/v1/invoices/:id` | Get invoice |
| PATCH | `/api/v1/invoices/:id` | Update invoice |
| DELETE | `/api/v1/invoices/:id` | Delete invoice |
| POST | `/api/v1/invoices/:id/send` | Send invoice |
| POST | `/api/v1/invoices/:id/pay` | Record payment |
| POST | `/api/v1/invoices/:id/void` | Void invoice |
| POST | `/api/v1/invoices/:id/write-off` | Write off bad debt or record its recovery |
| POST | `/api/v1/invoices/calculate-interest` | Preview exact overdue interest |
| POST | `/api/v1/invoices/:id/charge-interest` | Create and post an interest invoice |
| POST | `/api/v1/invoices/:id/submit-for-approval` | Submit a draft to its approval workflow |
| POST | `/api/v1/invoices/:id/approve` | Approve the assigned workflow step |
| POST | `/api/v1/invoices/:id/reject` | Reject the assigned workflow step |

Lifecycle responses retain numeric minor-unit totals and add matching `*Minor`
strings. Write-off defaults to `{action:"write-off",method:"direct"}`; allowance
is also supported. Recovery uses `{action:"recover",amount:1250}` or
`{action:"recover",amountMinor:"1250"}` in integer invoice-currency minor units;
omission defaults to invoice total. Interest overrides use decimal-major
`amount:12.5` or `amountExact:"12.50"`, or integer-minor `amountMinor:"1250"`
for USD. Dual aliases must agree. Calculated simple/daily compound interest uses
exact ratios and one final rounding; overdue duration supports up to 36500 days.
Recovery and interest responses add `recoveredMinor` and `interestAmountMinor`.

Send/void/bad-debt/approval decisions require `approve:invoices`; interest charges
and approval submission require `manage:invoices`. Issue-date locks are checked,
and interest checks today's posting date too. Sending requires complete active
revenue/control accounts and agreeing nonnegative line/header balances. Voiding
settled invoices requires refunding/unapplying payments or credits first. Each
operation commits its accounting/status/stock/approval effects atomically; saved
FX is retained, and voiding reverses stored amounts without reconversion.
Optional send email runs after accounting commits; delivery failures should be
retried using email operations. Monetary values remain within safe integer range;
unsupported amounts/FX return 422 instead of being rounded into legacy fields.
Matching MCP tools include `send_invoice`, `void_invoice`, `write_off_invoice`,
`recover_written_off_invoice`, `calculate_invoice_interest`,
`charge_invoice_interest` and the submit/approve/reject invoice tools.

Invoice list/detail reads retain numeric `subtotal`, `taxTotal`, `total`,
`amountPaid` and `amountDue` in stored minor units (USD cents), alongside exact
`*Minor` integer strings. Detail lines add `unitPriceMinor`, `amountMinor` and
`taxAmountMinor`; nested contacts add nullable `creditLimitMinor`. Quantities and
discount basis points retain their existing units. REST allocated payments add
`amountMinor`; MCP `get_invoice` retains its `{invoice}` envelope.

REST detail base amounts add nullable `*Minor` strings and an explicitly
lookup-derived `rateExact`/`rateDirection`/`rateBasis`. Base display supports matching
currency scales and safe FX products. It does not report saved invoice posting FX.
Summary returns numeric/string outstanding, overdue and aging amounts with one
`currencyCode` (null when empty). Mixed-currency outstanding invoices and unsafe
amounts/totals return 422 `LEGACY_NUMERIC_RANGE`. All numeric money remains limited
to the safe integer range. MCP `list_invoices`, `get_invoice` and
`get_invoice_summary` expose the same scoped read contracts.

Invoice create and draft update accept legacy decimal-major `unitPrice` numbers,
exact decimal-major `unitPriceExact` strings and integer-minor `unitPriceMinor`
strings. Aliases must agree: USD `12.50` maps to `1250` minor units. Numeric money
and exact inputs currently support only the safe integer monetary range. Quantity
is decimal physical units; discount is basis points. Create/update responses retain
`{invoice}` with numeric minor totals plus `*Minor` strings; create also returns
nullable `creditLimitWarning` with numeric/exact amounts. Draft deletion returns
`{success:true}`. MCP `create_invoice`, `update_invoice` and `delete_invoice` use
the same scoped atomic CRUD services and require `manage:invoices`.

REST create rounds unit price before quantity multiplication; draft update and
MCP create round the extended major price. Send `unitPriceExact` for sub-minor
precision. REST missing prices use price-list/item defaults; MCP retains zero
unless a price list is specified, and update omission remains zero. Price-list
currency must match; inventory fallback requires organization currency. Create
currency defaults to contact/org/USD in REST, USD in MCP. Old/new issue-date locks,
owned references and safe totals are checked before writes. Hard credit limits
return 403; mixed-currency credit comparisons and unsafe money return 422.
Lifecycle and bulk routes retain their separate contracts.

### Quotes
| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/quotes` | List quotes with pagination and optional status |
| POST | `/api/v1/quotes` | Create draft quote |
| GET | `/api/v1/quotes/:id` | Get quote with lines and contact |
| PATCH | `/api/v1/quotes/:id` | Update permitted draft headers or replace lines |
| DELETE | `/api/v1/quotes/:id` | Delete draft quote |
| POST | `/api/v1/quotes/:id/send` | Mark draft sent; optional email |
| POST | `/api/v1/quotes/:id/accept` | Accept an unexpired sent quote |
| POST | `/api/v1/quotes/:id/decline` | Decline sent quote |
| POST | `/api/v1/quotes/:id/convert` | Convert accepted quote to a draft invoice or progress bill |

Quote responses retain numeric currency minor units and add `subtotalMinor`,
`taxTotalMinor`, `totalMinor`, `billedTotalMinor`. Detail lines add
`unitPriceMinor`, `amountMinor`, `taxAmountMinor`; contact adds `creditLimitMinor`.
The list keeps `{data, pagination}`. Currency defaults to USD in both transports.

REST line `unitPrice` remains decimal major units; MCP `create_quote` and
`update_quote` numeric `unitPrice` remains integer minor units (USD cents).
Both accept `unitPriceExact` (decimal major-unit string) and `unitPriceMinor`
(canonical integer minor-unit string). Supplied aliases must agree: REST major
aliases agree exactly, minor aliases agree with the rounded major price. Prices
round before extending by physical quantity. Quantity is physical units on input,
hundredths on output; discounts and tax rates use basis points. Tax is exclusive.
All monetary inputs, individual rounded products and sums must fit the safe
integer range; larger exact strings return 422 without writes.

PATCH accepts contact, Gregorian issue/expiry dates, reference, notes, currency
and replacement lines. Retained minor amounts are never rescaled by currency
edits. Arbitrary database fields (including status, tenant and header totals) are
rejected. Replacement prices default to zero, with no price lookup. Creation
supports item/list lookup; items are lookup-only, and list currency must match.

Conversion accepts an empty body, `percentage` greater than zero through 100,
or `lines: [{quoteLineId, quantity}]`; nonempty lines take precedence. Percentage
bills a share of the original total, rounded per original line; omission bills the
exact remaining balance with deterministic residual allocation. It returns
`{quote, invoice, billing}` with numeric `invoiced`, `billedTotal`, `remaining`,
matching `*Minor` strings and `fullyBilled`. Partial bills remain accepted; only
zero remaining marks converted. Overbilling returns 400 with numeric/exact
`remaining` and `requested`. Malformed conversion JSON returns 400.

All writes require `manage:invoices`, organization-owned references and unlocked
issue dates; conversion also checks today's invoice date (UTC). Numbering,
headers, lines and billing totals commit atomically. Matching MCP operations are
`list_quotes`, `get_quote`, `create_quote`, `update_quote`, `delete_quote`,
`send_quote`, `accept_quote`, `decline_quote`, `convert_quote_to_invoice`.
MCP send records status only; REST email delivery follows the committed status
change and can fail independently. PDF/public/provider paths retain separate
contracts.

|--------|------|-------------|

| GET | `/api/v1/credit-notes/summary` | Single-currency totals and status breakdown |
| POST | `/api/v1/credit-notes/:id/send` | Recognize note and return linked stock; optional email |

Numeric money retains currency minor units and adds corresponding `*Minor`
strings. Credit-note headers include subtotal/tax/total/applied/remaining aliases;
lines include price/amount/tax aliases. Customer credits include original/remaining
aliases. Summary adds exact total/status amounts and rejects mixed currencies.
Available credits include `amountDueMinor` for the invoice and credit aliases.

REST line `unitPrice` remains decimal major units; MCP numeric prices are integer
minor units. Both accept `unitPriceExact` (decimal major string) and `unitPriceMinor`
(canonical minor string). Aliases must agree. Credit lines extend the unrounded
major price by physical quantity, then round gross/discount/exclusive tax; quantities
are physical units on input and hundredths on output, discounts basis points.
Creation defaults currency to USD and omitted prices to zero. PATCH permits
contact, original invoice, Gregorian issue date, reference, notes, currency and
replacement lines; arbitrary tenant/status/header-total fields reject.

Customer-credit create and both application operations accept positive integer
minor `amount` or canonical `amountMinor`, agreeing when both supplied. All money,
rounded products, taxes, sums and converted amounts must fit the JavaScript safe
integer range; larger valid exact inputs return 422 without committed changes.
Customer-credit currency defaults contact/org/USD; creation requires exactly one
cash `bankAccountId` or asset `depositAccountId`, and bank currency must match.
Application optionally accepts Gregorian `date` for customer credits, defaulting
to today (UTC). Both credit types require matching invoice customer/currency and
eligible state/positive balance. Credit-note application records allocations with
no second AR journal; customer-credit application posts DR deposits / CR AR.

Corresponding MCP tools are `list_credit_notes`, `get_credit_note`,
`create_credit_note`, `update_credit_note`, `delete_credit_note`,
`get_credit_note_summary`, `send_credit_note`, `apply_credit_note`,
`void_credit_note`, `list_customer_credits`, `get_customer_credit`,
`create_customer_credit`, `apply_customer_credit`, `list_invoice_available_credits`.
Writes require `manage:credit-notes` or `manage:payments` and open periods. Atomic
services protect numbering, references, GL, stock and carrier/invoice balances.
Note void uses saved FX/base amounts and new return quantities/costs. Customer
application retains application-date FX; complete carrying-value settlement is
separately qualified. Standard/serial/lot returns reject; consumed FIFO return
layers reject. Optional email delivery follows commit and can fail independently;
retry email separately. PDF/provider and full-domain contracts remain separate.

### Journal Entries
| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/entries` | List entries |
| POST | `/api/v1/entries` | Create entry |
| GET | `/api/v1/entries/:id` | Get entry |
| PUT/PATCH | `/api/v1/entries/:id` | Replace a draft entry header and lines |
| DELETE | `/api/v1/entries/:id` | Delete a draft entry and its lines |
| POST | `/api/v1/entries/:id/post` | Post entry |
| POST | `/api/v1/entries/:id/void` | Void entry |

Journal CRUD accepts line `debitAmountMinor` and `creditAmountMinor` canonical
nonnegative integer strings alongside legacy `debitAmount`/`creditAmount` minor-unit
numbers. Both aliases must agree; an omitted side defaults to zero. Values and
per-entry sums must fit the current safe-number workflow (at most 9007199254740991).
`rateExact` accepts saved quote-per-base decimal strings exactly representable in
positive int32 millionths; dual `exchangeRate` must agree. Amount/rate range
failures return 422 with `LEGACY_NUMERIC_RANGE`, before writes.

REST detail retains historical fixed-two-decimal `debitAmount`/`creditAmount`
strings and adds raw `*Minor` strings plus saved exact FX metadata. REST list
retains its decimal-string `totalDebit` and adds `totalDebitMinor`. These aliases
never rescale stored values by currency. Automated entries can store already-base
amounts while the line currency tags the original document; reads do not apply FX
again. Mixed manual-currency list totals remain raw stored sums.

Creation requires `create:entries`; replacement/deletion requires `edit:entries`.
References must belong to the organization, and period locks/closed years apply.
Replacement/deletion is draft-only. MCP `list_entries`, `get_entry`, `create_entry`,
`update_entry` and `delete_entry` provide the corresponding operations, with
minor-unit numeric output plus exact aliases. REST create retains its existing
base-balance check for mixed currencies/rates, including per-line rounding slack
and safe FX-product limits; REST replacement and MCP create/update retain raw
debit/credit equality. These aliases do not enable full-int64 domain posting.
Post/void REST responses also include exact leg aliases and saved FX. Posting
requires `post:entries` and rechecks locks; void requires `void:entries` and writes
an atomic mirror without another FX conversion. Recode requires `edit:entries`,
scoped target dimensions and unlocked dates; `draftOnly=false` explicitly includes
posted entries. MCP lifecycle tools expose the corresponding header/count outputs.

REST bulk import/preview legacy `debit`/`credit` is fixed-two-decimal input:
`"12.50"` means 1250 stored units. MCP `import_journal_entries` and the new
`preview_journal_entries` retain integer cents: `1250` means 1250 units. Both accept
canonical `debitAmountMinor`/`creditAmountMinor` strings, with dual agreement and
safe-number value/group-sum limits. Prefer REST decimal strings; numeric decimal
input above `2^45 - 1` requires text or exact aliases. Extra fractional digits and
malformed inputs are rejected rather than rounded. Preview adds `totalDebitMinor`,
`totalCreditMinor` and `imbalanceMinor` strings. Imported legs retain legacy USD/
1:1 defaults; currency-aware decimal import is not introduced.

Import requires `manage:entries`, plus `post:entries` for `post=true`. Malformed
wire input fails before job creation. Business-invalid groups are reported in the
job; valid groups commit independently with atomic headers/legs. Sources are
quickbooks, xero, freshbooks, wave or custom, and grouped dates/memos/references
must agree. Full exact domain qualification remains separate work.

### Recurring Journals

| Method | Path | Description |
|--------|------|-------------|
| GET/POST | `/api/v1/recurring-journals` | List/create journal templates |
| GET/PATCH/DELETE | `/api/v1/recurring-journals/:id` | Read/edit/soft-delete a template |
| POST | `/api/v1/recurring-journals/:id/pause` | Toggle active/paused |
| POST | `/api/v1/recurring-journals/run` | Run this organization's due templates |

REST and MCP retain safe numeric **stored minor-unit** `debitAmount` and
`creditAmount` (USD cents), and add canonical `debitAmountMinor` and
`creditAmountMinor` strings on legs. Both input aliases must agree. Each leg has
one positive side; summed debits equal credits and must fit safe integers
(`<=9007199254740991`). Malformed/conflicting inputs fail validation; unsupported
numeric ranges return 422 `LEGACY_NUMERIC_RANGE` before mutation.

Saved `currencyCode` is retained on partial edits and posted verbatim without
rescaling. Templates have no configurable FX storage: rate aliases explicitly
represent fixed `exchangeRate:1000000`, `rateExact:"1"` and
`rateDirection:"quote_per_base"`. Nonidentity FX is rejected. This preserves the
existing template posting behavior, not currency-aware base conversion.

Dates are canonical Gregorian YYYY-MM-DD; startDate is immutable on edits.
Nullable endDate/maxOccurrences/reference/notes clear with null. Editing lines
fully replaces the balanced legs atomically. Writes require `manage:recurring`
and active organization-owned accounts/cost centers. Corresponding MCP tools are
`list_recurring_journals`, `get_recurring_journal`, `create_recurring_journal`,
`update_recurring_journal`, `set_recurring_journal_status`,
`pause_recurring_journal`, `delete_recurring_journal` and `run_recurring_journals`.

Generation validates retained amounts and dimensions, then commits each
**template's** entire catch-up and schedule together under a row lock. Concurrent
runs of that template do not duplicate entries. Locked/closed dates consume an
occurrence without posting; malformed templates fail without consuming their
schedule. Resume keeps nextRunDate and catches up. An earlier template can remain
committed if a later one fails; runs are not atomic across all templates.

These JSON routes use an existing bearer link token. Portal access is limited to
its contact and organization; revoked, expired or deleted-contact grants fail.
Existing numeric money fields retain their units and gain matching canonical
`*Minor` strings. For example, `total: 1250` also returns `totalMinor: "1250"`.
Amounts must fit the signed JavaScript safe-integer range; unsupported stored
amounts or sums return 422 with `LEGACY_NUMERIC_RANGE`.

## Exact recurring invoice prices

Recurring invoice endpoints (`/api/v1/recurring-invoices` and invoice targets of
`/api/v1/recurring`) and MCP `create_recurring_template` with `type: "invoice"`
accept additive `unitPriceExact` decimal-major strings and `unitPriceMinor`
canonical currency-minor integer strings alongside numeric decimal-major
`unitPrice`. For USD, `12.50`, `"12.50"` and `"1250"` denote the same price.
If several aliases are supplied, they must agree. Stored line `unitPrice` remains
numeric minor units and gains `unitPriceMinor`; preview `lineTotal` gains
`lineTotalMinor` and a currency code. Preview totals remain before discount/tax.

Prices, line products and totals must fit safe integers (absolute value at most
9007199254740991). Invalid aliases reject before writes. Schedule dates use
Gregorian `YYYY-MM-DD`, occurrence caps fit int32, and every reference belongs to
the organization. Template FX inputs are unsupported; automated posting resolves
historical FX for each occurrence and saves exact posting rates. Changing currency
across minor-unit scales requires a new template with explicit prices.

Generation atomically commits invoice numbers, documents, automated posting and
schedule advancement per template. Locked dates, missing posting FX or invalid
saved data leave the schedule pending for retry. Auto-send attempts email after
commit; delivery failure retains the posted invoice. MCP also provides
`delete_recurring_invoice` and `preview_recurring_invoice`. Other document types
retain their existing numeric price contracts.

# AI-030 - Persist scoped clarification and versioned safe continuation

## Objective and implementation scope

Child of AI-023. Build durable awaiting-input questions and shared REST/MCP answer/resume services on AI-029 observation. Do not infer approval or rely on model conversation memory for authority.

## Inputs

[AI-023](AI-023.md), [execution contract](../docs/AI_EXECUTION_CONTRACT.md), [product experience](../docs/AI_PRODUCT_EXPERIENCE.md).

## Acceptance criteria

- [ ] Persist bounded questions, scoped candidate references and the pending input version with retention and content-free notifications; revalidate display access.
- [ ] Share strict described own/org REST/MCP answer schemas, expected versions and idempotency; reject stale, forged, deleted, inaccessible or invalid choices and distinguish clarification from approval.
- [ ] Atomically accept one pending answer and queue continuation under current identity/config/policy without resetting budgets/deadlines or replaying effects; cancellation, expiry and concurrent answers fail safely.
- [ ] Generate migrations for schema changes and verify real database REST/MCP concurrency, negatives, retention and recovery plus typecheck/lint, capability/coverage and controller/diff checks.

## Verification

Disposable loopback PostgreSQL, real routes/registered MCP, deterministic races and static gates. No build, dev server or live provider.

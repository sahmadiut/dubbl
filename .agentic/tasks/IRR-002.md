# IRR-002 - Rehearse IRR backup restore and financial rollback

## Objective and implementation scope

Demonstrate a disposable PostgreSQL backup/restore rehearsal with large IRR
amounts and exact independent reconciliation before and after restore. Define
what disabling IRR stops and how existing IRR organizations and historical
postings remain interpretable. Supply bounded IRR evidence to QA-005 without
claiming its broader deployment rehearsal is complete.

All technical reviews must be honestly attributed to Codex. Preserve Stripe
under DEC-008, integer minor units, canonical money contracts and existing data.
No new human-release or independent native-language approval is implied.

## Inputs

- [IRR baseline](IRR-001.md), [readiness map](../registries/IRR_READINESS.md) and [QA-005](QA-005.md).
- [Migration requirements](../sources/SOURCE.md#database-and-currency-migration).
- Existing `tests/integration/backups.test.ts`, its worker and money migration fixtures.

## Acceptance criteria

- [ ] Back up and restore representative disposable IRR data with measured recovery time; reconcile counts, nulls, checksums, account balances, AR/AP, bank and retained earnings against independent SQL.
- [ ] Prove stored IRR minor units and low digits survive restoration, migration replay and large values; never infer a rial/toman factor or narrow unrepresentable bigint history.
- [ ] Document and test the distinction between rejecting new IRR selections, ongoing writes by existing IRR organizations, and operational write suspension; an environment flag alone must not be described as a full rollback.
- [ ] Deliver the IRR recovery evidence and concrete stop/restore/reconcile procedure to QA-005; identify production snapshot/version/volume rehearsal separately and leave global QA-005 acceptance open.

## Verification

Reuse and extend `tests/integration/backups.test.ts` and money migration
fixtures against disposable loopback PostgreSQL. Record PostgreSQL version,
fixture size, backup/restore commands without credentials, recovery time,
reconciliation and cleanup. Use typecheck/lint only if application code changes.

# AI-047 - Bind journal previews to current business-approval policy

## Objective and implementation scope

Qualify business-policy observation for the existing manual-journal posting
adapter and durable proposal revisions. AI-048 expands payment/deletion/sending;
AI-046 retains combined integration, AI-043 decisions and AI-044 dispatch.

## Inputs

[AI-046](AI-046.md), [preview contract](../docs/AI_ACTION_PREVIEWS.md),
[batch contract](../docs/AI_ACTION_BATCHES.md), and existing approval domain policy.

## Acceptance criteria

- [x] Evaluate saved journal workflow conditions using the existing approval engine and fail closed on invalid policy, steps and cross-organization references; report bounded identity-free next actor categories.
- [x] Bind current policy, resource and approval metadata to journal fingerprints and persisted proposals; reject stale policy/resource/request/action changes and regenerate on explicit revision without extending expiry.
- [x] Never treat status-only historical approvals as resource-bound approval, authorize self-approval, mutate approval/business records, approve, dispatch or expand the automatic catalog.
- [x] Verify actual REST/MCP/disposable SQL matching/nonmatching/malformed policy, actor/scope, stale revisions, bounds, read-wait revocation and no effects; run static/capability/controller checks and document limitations.

## Verification

Focused real REST/MCP/disposable-loopback SQL tests, typecheck/lint, capability and
tool coverage, controller validation and diff checks. No build/dev/live provider.

## Handoff

Implemented the shared observation-only business-policy evaluator for manual
journal previews and persisted proposal revisions. Adapter version 2 binds exact
resource and policy/request/action snapshots; version-one proposals read stale
and can be explicitly revised under their original expiry. Matching conditions
use the existing approval engine. Invalid/ambiguous/oversized policies fail
closed, actor categories expose no identities, and self-assignment requires
repair. Historical approval status never satisfies exact resource approval.

Actual REST/MCP/disposable SQL preview/batch and approval/runtime/lifecycle
regressions pass (5 integration suites); 14 focused unit tests, typecheck, lint,
schema drift, capability/coverage, legacy money and controller/diff checks pass.
Full lint retains 20 existing warnings. Money inventory remains failed at 1447
baseline errors with zero changed verifier inputs. See
[attempt](../evidence/AI-047-attempt-1.md), [self-review](../evidence/AI-047-review-1.md)
and [policy contract](../docs/AI_BUSINESS_POLICY_PREVIEWS.md).

Next AI-048 expands the finite domain-adapter set. AI-046/042/008 retain independent
integration, AI-043/044 decisions/dispatch remain open, and the ordinary model
catalog remains seven read/draft tools. No business mutation, approval, sensitive
dispatch, provider call, schema migration, rollout activation or push is claimed.

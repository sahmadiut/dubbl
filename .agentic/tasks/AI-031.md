# AI-031 - Execute and recover the metered bounded provider worker

## Objective and implementation scope

Child of AI-023. Implement its actual provider/tool executor using lifecycle leases, safe observation and durable clarification. This child does not accept AI-023 or AI-007, enable rollout or qualify a live provider.

## Inputs

[AI-023](AI-023.md), AI-002..006 source/evidence, [execution contract](../docs/AI_EXECUTION_CONTRACT.md), [product experience](../docs/AI_PRODUCT_EXPERIENCE.md).

## Acceptance criteria

- [x] Implement explicit polling worker entrypoint, graceful shutdown and fenced lifecycle ownership; deterministic provider scenarios exercise dependent tools, grounded final links, clarification/resume and truthful queue/unavailable conditions.
- [x] Recheck current identity, configuration snapshots, policy and kill switch immediately before every provider/tool action; enforce step/request/token/output/time/cost limits with usage reservations and trusted callbacks, including retries and unknown usage.
- [x] Persist ordered idempotent operations/events; retry only bounded transient reads/provider attempts and reconcile uncertain writes without duplicate effects. Cancellation/restart preserve partial effects and do not reset execution budgets.
- [x] Treat prompts/documents/tools as untrusted data and publish safe summaries only. Verify provisional streaming versus confirmed persisted results, live permission checks, cursor loss/reconnect, delayed responses, cancellation during effects and bounded histories through real REST/MCP/database and deterministic provider fault/race tests.
- [x] Pass typecheck/lint, disposable database integrations, capability/coverage/schema drift and controller/diff checks; document explicit worker startup and unqualified provider/hosting limitations.

## Verification

Deterministic fake provider and real registered tools/routes/database; separate process restart and concurrency tests. No live provider, build or dev server.

## Handoff

Split into required AI-032 (durable fenced tool operations) and AI-033 (actual metered provider loop, polling process, streaming and fault qualification). Original criteria remain open for independent integration after both children. AI-023 independently integrates its children against its unchanged acceptance criteria.

Independently integrated the completed children using the actual polling worker,
encrypted raw adapter, metering, registered business tools, REST/MCP observation
and SQL assertions. Extended the combined runtime fixture to cancel/revoke policy/
activate the kill switch while a second raw response is incomplete, retaining the
first exact-money draft and unknown charge without accepting a late call. A fresh
poller after clarification obeys a stricter live budget before transmission and
preserves original attempts, charges, configuration and deadline. Disabled-provider
queued observation is truthful and read-only. See
[attempt evidence](../evidence/AI-031-attempt-1.md) and
[self-review](../evidence/AI-031-review-1.md).

Worker startup/shutdown and qualification limits remain in
[AI_WORKER](../docs/AI_WORKER.md). Provisional output is bounded server-status
snapshot polling; raw model text/token streaming and live provider/hosting/rollout
are unqualified. AI-023 and AI-007 retain their original acceptance obligations.
No schema, public REST/MCP contract or production runtime change was required.

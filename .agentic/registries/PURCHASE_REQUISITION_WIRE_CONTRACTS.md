Every operation uses server-created org AuthContext and direct Drizzle services.
MCP registration already exists in tools/index.ts; the rewritten file retains
that registerPurchaseRequisitionTools function and all six legacy tool names,
adding distinct edit/delete/submit operations. Every input field is described.
Reads require authentication; create/edit/delete/submit/convert require
manage:purchases; approve/reject require approve:purchases. API keys select their
own organization despite conflicting x-organization-id headers. Foreign/deleted
IDs are 404; wrong transition is 400 (formerly some wrong-state paths returned
404). Validation is 400, period/fiscal lock is 422, unsupported numeric money is
422 with LEGACY_NUMERIC_RANGE. MCP reports isError with details/status where the
shared wrapper supplies them; it does not guarantee HTTP status on Zod errors.

List/detail both return supplier and sorted lines. Safe contact creditLimit adds
creditLimitMinor. Historical inactive/deleted references remain readable in the
same tenant; foreign contact/account/tax/link references reject before disclosure.
List/count use a repeatable-read read-only transaction, independent currency
labels and ordinary numeric pagination/counts, without a cross-currency sum.
Defaults: page 1, limit 50; limit 1..100, maximum page 21,474,836. REST retains
parsePagination coercion/clamping before bounded service parsing. Status filters
are validated; arbitrary status strings no longer silently remove the filter.

## Units, exact aliases and supported ranges

| Field | Input | Saved/output |
|---|---|---|
| unitPrice | Optional decimal major-unit Number (USD 12.50), defaults zero if all prices omitted | Rounded integer currency minor units (USD 1250) |
| unitPriceExact | Optional ASCII signed decimal major string, <=20 whole/18 fractional digits | Same rounded minor price; unrounded ratio used for extension |
| unitPriceMinor | Optional canonical signed int64 integer string, within safe workflow bounds | Same integer currency minor price |
| quantity | Decimal physical-unit Number, defaults 1 | Signed int32 hundredths, e.g. 1.5 -> 150 |
| taxRateId | Optional tenant UUID reference | Retained reference; no tax calculation |
| subtotal/taxTotal/total | Calculated by server | Integer currency minor units plus named *Minor strings; taxTotal=0 |
| line unitPrice/amount/taxAmount | Calculated by server | Integer currency minor units plus named *Minor strings; taxAmount=0 |
| currencyCode | Active currency code, defaults USD in REST/MCP | Label and frozen currency scale; no FX conversion |
| contactId/accountId | Optional tenant supplier/expense-account UUID; null allowed | Same reference or null |
| requestDate/requiredDate | Gregorian YYYY-MM-DD; requiredDate can be null | PostgreSQL date-only |
| approvedAt/rejectedAt/timestamps | Generated by server | UTC ISO instants in JSON |
| reference/notes/reason | Optional strings; metadata can be null | Same text; omitted rejection reason becomes null |

Header and line money supports [-9007199254740991,9007199254740991], including
above-int32/signed amounts. The transitional ORM and legacy-number consumers do
not support full int64 business values. Unsupported prices, products, final sums
and saved constituents reject before writes; no rounded-number-to-string repair.
Minor aliases are canonical ASCII signed integers: no exponent, whitespace,
localized digits, leading zeros, fractions, negative zero or out-of-int64 values.
Exact major strings reject exponent/whitespace/localized digits and malformed
syntax. Numeric aliases use their shortest decimal spelling, including exponent
notation, then bigint ratios. Numeric and exact major aliases agree exactly;
minor aliases agree with the separately rounded major price.

Extension multiplies original decimal quantity by original major-price ratio,
rounding signed ties toward +infinity. Stored quantity and unit price round
separately, preserving existing requisition semantics without binary-float math.
Thus USD quantity 3 at 0.005 stores price 1 but extended amount 2; conversion
copies 2, never recomputes 3. Tax is always zero even with a taxRateId. No discount
input/calculation exists. Quantities range [-21474836.48,21474836.47], rounded to
signed int32 hundredths. Zero/negative quantities are retained as legacy draft/PO
values; downstream PO-to-bill conversion still requires positive quantities.
Arrays contain 1..1000 lines. Existing USD 1250 remains 1250, without magnitude
rescaling. JPY/KWD respect their scales; pure IRR scale fixtures do not change
functional-currency/production readiness flags.

## State, locks, conversion and compatibility

Draft edits whitelist contactId, requiredDate, reference and notes. Lines,
currency, number and requestDate stay fixed; unknown CRUD fields retain legacy
stripping. PUT permits only optional status='submitted', and atomically applies
metadata and the draft submission. The old UI used a redundant empty edit then
PUT status which was silently stripped, and pretended success locally. It now
issues one actual submission and uses the returned status. MCP has separate
submit/edit tools. Arbitrary status changes cannot bypass approval.

Edit/delete/submission are draft-only; approve/reject are submitted-only;
conversion is approved-only with a supplier. Approved/converted requests cannot
be amended/deleted to invalidate approval or orphan their order. These stricter
write restrictions are intentional compatibility corrections. Soft-delete
retains lines for historical/trash behavior. There is no automatic workflow
routing, request-change action, notification, email or new approval queue.

All writes lock organization then header/lines and relevant tenant references.
Fresh input/submission/decision/conversion requires available active references;
read/delete/history validation allows historical same-tenant references. Saved
currency/dates, int32 quantities, zero tax, exact header/line balance and
convertedPoId/status agreement are checked before mutations. Generated numbering
uses saved sequences and existing numeric REQ/PO forms, including deleted rows;
int32 exhaustion rejects. Organization locking coordinates first sequence creation
and PO creation with conversion; the exported PO allocator is reused within the
same transaction. Other legacy/bulk/trash writers remain their assigned gates.

Strict request-date period/fiscal locks apply to every mutation, without advisor
bypass. Conversion also checks today's UTC PO issue date. requiredDate is only a
delivery target, not the accounting lock date. Shared period-lock configuration
writers/races remain later qualification; no global lock-policy change is claimed.
Number/header/lines/status/link/audit commit atomically. DTO/JSON preflight occurs
before commit. Conversion copies saved line prices, quantities, net/tax and header
amounts, currency, required date as delivery date, reference and notes. It uses
UTC today for PO issueDate, creates a draft PO and marks/links the requisition.
Repeated/concurrent conversion rejects the loser; it never creates a second PO.
There is no public idempotency key or success replay contract. Failure injection
at requisition/PO/line/link/audit stages proves no partial business writes or
number consumption. No posted accounting history is rewritten or journal posted.

## What is MCP?

The [Model Context Protocol](https://modelcontextprotocol.io) (MCP) is an open standard that lets AI coding agents and assistants interact with external tools and data sources. dubbl's built-in MCP server gives any MCP-compatible agent direct access to your accounting data -- creating entries, managing invoices, generating reports, and more.

## Prerequisites

- **Any plan** -- MCP access is available on all plans, including Free
- Any MCP-compatible client (Claude Desktop, Claude Code, Cursor, Windsurf, Cline, VS Code Copilot, or other MCP-enabled agents)

## Connecting Your Agent

Any MCP-compatible agent can connect to dubbl's MCP server. The server uses Streamable HTTP transport at `/api/mcp` and OAuth 2.1 for authentication. Most agents handle the OAuth flow automatically -- they will open a browser window for you to sign in and authorize access on first connect.

The examples below use `https://dubbl.dev/api/mcp`. If you are self-hosting, replace `dubbl.dev` with your own domain.

### Claude Desktop

Add to your Claude Desktop config (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "dubbl": {
      "url": "https://dubbl.dev/api/mcp"
    }
  }
}
```

### Claude Code

```bash
claude mcp add dubbl --transport streamable-http https://dubbl.dev/api/mcp
```

### Cursor

Go to **Cursor Settings > MCP** and add a new server, or add to `.cursor/mcp.json` in your project:

```json
{
  "mcpServers": {
    "dubbl": {
      "url": "https://dubbl.dev/api/mcp"
    }
  }
}
```

Cursor auto-detects Streamable HTTP transport from the URL and handles OAuth automatically.

### Windsurf

Go to **Windsurf Settings > Cascade > MCP** and click **View raw config**, or edit `~/.codeium/windsurf/mcp_config.json` directly:

```json
{
  "mcpServers": {
    "dubbl": {
      "serverUrl": "https://dubbl.dev/api/mcp"
    }
  }
}
```

### VS Code (GitHub Copilot)

Add to `.vscode/mcp.json` in your workspace (available in VS Code 1.99+):

```json
{
  "servers": {
    "dubbl": {
      "type": "http",
      "url": "https://dubbl.dev/api/mcp"
    }
  }
}
```

Or add to your user `settings.json` to make it available across all workspaces:

```json
{
  "mcp": {
    "servers": {
      "dubbl": {
        "type": "http",
        "url": "https://dubbl.dev/api/mcp"
      }
    }
  }
}
```

### Other MCP Clients

Any agent that supports the MCP Streamable HTTP transport can connect. Point it at:

```
https://dubbl.dev/api/mcp
```

The client will discover OAuth endpoints automatically via the `/.well-known/oauth-authorization-server` metadata endpoint.

## OAuth Flow

dubbl uses OAuth 2.1 with PKCE for MCP authentication:

1. The MCP client discovers OAuth endpoints via `/.well-known/oauth-authorization-server` on the MCP endpoint
2. The client registers dynamically at `/api/mcp/oauth/register`
3. The client redirects you to `/api/mcp/oauth/authorize` to sign in
4. You select an organization and approve the connection
5. The client receives an authorization code and exchanges it for access/refresh tokens at `/api/mcp/oauth/token`
6. Access tokens expire after 1 hour; refresh tokens last 30 days

## Available Tools

### Organization
- `get_organization` -- Get current organization details

### Chart of Accounts
- `list_accounts` -- List all accounts with optional type filter
- `get_account` -- Get account with calculated balance
- `create_account` -- Create a new account
- `update_account` -- Update account details
- `delete_account` -- Delete an account (fails if it has transactions)

### Journal Entries
- `list_entries` -- List entries with status/date filters
- `get_entry` -- Get entry with line items
- `create_entry` -- Create a new entry (debits must equal credits)
- `post_entry` -- Post a draft entry
- `void_entry` -- Void a posted entry (creates reversing entry)

### Contacts
- `list_contacts` -- Search and filter contacts
- `get_contact` -- Get contact details
- `create_contact` -- Create a customer, supplier, or both
- `update_contact` -- Update contact details

### Invoices
- `list_invoices` -- List invoices with filters
- `get_invoice` -- Get invoice with line items
- `create_invoice` -- Create an invoice with line items
- `void_invoice` -- Void an invoice
- `pay_invoice` -- Record a payment (amount in cents)

### Bills
- `list_bills` -- List bills with status filter
- `create_bill` -- Create a bill with line items
- `get_bill` -- Get bill detail with exact money aliases and base display
- `get_bill_counts` -- Count bills and amount due per status and currency
- `update_bill` -- Edit draft bill header or replace lines atomically
- `delete_bill` -- Soft-delete a draft bill atomically
- `receive_bill` -- Receive a draft with atomic ledger, stock and GRNI posting
- `approve_bill` -- Approve a pending bill with atomic posting on final approval
- `reject_bill` -- Reject a pending bill back to draft with audit
- `pay_bill` -- Record a payment (amount in cents)
- `void_bill` -- Void an unsettled bill using saved ledger, FX and stock values

### Supplier debit notes
- `list_debit_notes` -- List supplier notes with safe numeric money and exact aliases
- `get_debit_note` -- Read supplier, lines and recognition journal
- `create_debit_note` -- Create a draft; numeric prices are integer minor units
- `update_debit_note` -- Edit a draft or replace its lines atomically
- `delete_debit_note` -- Soft-delete a draft and retain its lines
- `send_debit_note` -- Recognize AP credit and qualified complete stock returns
- `apply_debit_note` -- Offset recognized matching supplier/currency/carrying-FX bills
- `void_debit_note` -- Reverse saved journal/stock and unwind carrier allocations

Debit-note `unitPriceExact` is decimal major units and `unitPriceMinor` integer
minor units; combined aliases must agree. Numeric prices retain integer minor
units (USD cents). Amounts and derived values must fit safe integers. Sending
recognizes accounting only; use `send_document_email` for delivery. Partial/GRNI
stock returns and differing carrying-FX settlement reject pending qualification.

### Purchase requisitions
- `create_purchase_requisition` -- Create a draft with exact major/minor price aliases
- `list_purchase_requisitions` -- List scoped requisitions, supplier and lines
- `get_purchase_requisition` -- Get detail with exact money aliases
- `update_purchase_requisition` -- Edit draft supplier/date/reference/notes
- `delete_purchase_requisition` -- Soft-delete a draft, retaining lines
- `submit_purchase_requisition` -- Submit a draft for approval
- `approve_purchase_requisition` -- Approve a submitted request
- `reject_purchase_requisition` -- Reject a submitted request with a reason
- `convert_purchase_requisition` -- Copy approved saved amounts to one draft PO

### Purchase orders
- `create_purchase_order` -- Create a draft with exact major/minor price aliases
- `list_purchase_orders` -- List scoped orders, supplier and lines
- `get_purchase_order` -- Get order detail with exact money aliases
- `get_purchase_order_counts` -- Count and total orders per status and currency
- `update_purchase_order` -- Edit a draft atomically with legacy PATCH tax policy
- `delete_purchase_order` -- Soft-delete a draft and remove its lines
- `send_purchase_order` -- Mark sent and optionally deliver email after commit
- `convert_po_to_bill` -- Convert remaining or partial quantities exactly

### Reports
- `trial_balance` -- Trial balance report
- `balance_sheet` -- Balance sheet
- `profit_and_loss` -- P&L with date range
- `aged_receivables` -- AR aging buckets
- `aged_payables` -- AP aging buckets

## Amount Conventions

- All monetary amounts in tool inputs/outputs are in **integer cents** (e.g. `1250` = $12.50)
- Invoice/bill/purchase-order/requisition write `unitPrice` is decimal major units (USD 12.50); `unitPriceExact` is an exact major decimal string and `unitPriceMinor` is an integer minor string. Quantity is decimal physical units. Bill write responses include exact header `*Minor` aliases; supported amounts remain signed safe integers. See [API Reference](/docs/api-reference) for currency, rounding and duplicate policies.
- Exchange rates are stored as integers with 6 decimal places (`1000000` = 1.0)

## Testing

### With MCP Inspector

The [MCP Inspector](https://github.com/modelcontextprotocol/inspector) is the easiest way to test the MCP server interactively during development.

```bash
# Start the dev server first
pnpm dev

# Launch MCP Inspector pointed at your local instance
npx @modelcontextprotocol/inspector --url http://localhost:3000/api/mcp
```

The Inspector will open in your browser and walk you through the OAuth flow. Once authenticated, you can browse available tools, invoke them with custom inputs, and inspect the JSON-RPC responses.

### Manual OAuth Flow

If you want to test the OAuth flow step by step:

**1. Check metadata discovery**

```bash
curl http://localhost:3000/.well-known/oauth-authorization-server/api/mcp
```

This should return JSON with all OAuth endpoint URLs.

**2. Register a client**

```bash
curl -X POST http://localhost:3000/api/mcp/oauth/register \
  -H "Content-Type: application/json" \
  -d '{"redirect_uris": ["http://localhost:9999/callback"], "client_name": "Test Client"}'
```

Save the `client_id` from the response.

**3. Start the authorization flow**

Open this URL in your browser (replace `CLIENT_ID` with the value from step 2):

```
http://localhost:3000/api/mcp/oauth/authorize?client_id=CLIENT_ID&redirect_uri=http://localhost:9999/callback&code_challenge=TEST_CHALLENGE&code_challenge_method=S256&state=test123&response_type=code
```

You will be redirected to sign in (if needed) and then to the consent page. After approving, you'll be redirected to the callback URL with a `code` parameter.

**4. Exchange code for tokens**

```bash
curl -X POST http://localhost:3000/api/mcp/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "authorization_code",
    "code": "THE_CODE_FROM_STEP_3",
    "redirect_uri": "http://localhost:9999/callback",
    "client_id": "CLIENT_ID",
    "code_verifier": "THE_VERIFIER_MATCHING_YOUR_CHALLENGE"
  }'
```

This returns `access_token` and `refresh_token`.

**5. Call the MCP endpoint**

```bash
curl -X POST http://localhost:3000/api/mcp \
  -H "Authorization: Bearer mcp_at_YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2025-03-26",
      "capabilities": {},
      "clientInfo": { "name": "test", "version": "1.0" }
    }
  }'
```

**6. List available tools**

```bash
curl -X POST http://localhost:3000/api/mcp \
  -H "Authorization: Bearer mcp_at_YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/list",
    "params": {}
  }'
```

**7. Call a tool**

```bash
curl -X POST http://localhost:3000/api/mcp \
  -H "Authorization: Bearer mcp_at_YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "get_organization",
      "arguments": {}
    }
  }'
```

## Bill CSV import

Use `get_import_template` with `entityType: "bills"`, then `preview_bill_import`
and `import_bills` with flat mapped rows. Prices and extended amount overrides
use decimal **major** units in REST and MCP. `lineUnitPriceExact`/`lineAmountExact`
are decimal-major strings; `lineUnitPriceMinor`/`lineAmountMinor` are integer
currency minor strings. Aliases must agree; money/products/group totals must fit
safe integers. Currency defaults USD; names/accounts resolve in the current org.

Nonempty `billNumber` groups lines; omission/blank creates separate bills. Import
requires `manage:bills` and `fileName`, checks periods and commits each draft,
number, lines and create audit atomically. Returned job totalRows counts input
lines; processedRows/errorRows count documents. Failures can be partial; repeating
creates new bills. Preview writes nothing and returns per-line validation with
numeric stored minor amounts plus named `*Minor` strings. No ledger/payment
posting occurs; full-int64/production currency qualification remains separate.

## Bank categorization tools

Use `categorize_bank_transaction` for one category or `split_bank_transaction`
for exact allocations. Split `amount` is an integer in bank-currency minor units
(USD cents); `amountMinor` is its exact integer-string alias. Both must agree.
The allocations must total the absolute saved bank movement. A repeated plain
categorization corrects its journal with saved FX; split repeats fail.

`bulk_cash_code` codes up to 200 movements to one account;
`bulk_categorize_bank_transactions` accepts per-item accounts and dimensions.
Each item commits independently, with reported failures and no duplicate posting
on retries. These tools require `manage:banking`.

`create_expense_from_bank_transaction` requires `manage:expenses` and records an
outgoing movement as an already-paid, journal-linked claim. Numeric item `amount`
uses integer minor units (USD 1250 = $12.50), `amountMinor` an integer string and
`amountExact` a decimal major-unit string ("12.50"). All aliases must agree;
currency and total must match the bank. It returns `expenseClaim` with numeric
`totalAmount`, exact `totalAmountMinor`, and `journalEntryId`. Repeated creation
fails. Supported money and posting totals are bounded by 9007199254740991 minor
units; larger exact input fails visibly rather than rounding.

## Bank document matching tools

`match_to_invoice` and `match_to_bill` settle a complete incoming/outgoing bank
statement line. `split_to_documents` allocates it across distinct recognized
invoices/bills of the same contact/currency. Numeric `amount` means integer
currency minor units (USD 1250 = $12.50); `amountMinor: "1250"` is its canonical
exact alias. They must agree and cover the full line; partial coverage, mixed
contacts/currencies and overpayments fail. Optional date defaults to the statement
date; method defaults to bank_transfer. Requires `manage:banking`.

Payment, saved carrying/cash FX journal, allocation, document updates, bank links
and audit commit together. Responses retain transactionId, payment and document
status; payment adds amount/amountMinor/currencyCode/journalEntryId. Split results
include allocations with amount/amountMinor/newStatus. Noncash credit/debit/
prepayment carriers are retained separately from new cash settlement.

`match_to_existing_payment` links posted cash on the same bank/currency/amount/
direction and returns transactionId/paymentId/journalEntryId. It uses saved FX
without a current lookup or another posting; noncash carriers fail.
`match_to_existing_journal` links an owned unreversed posted journal whose net
bank leg exactly matches the line, returning transactionId/matchType/journalEntryId.
Direct journal matching supports base-currency identity FX; foreign cash uses
existing-payment matching. `get_bank_invoice_matches` returns same-currency
invoice suggestions and open invoices with numeric money and exact minor aliases.

All money/totals must fit safe integers through 9007199254740991; larger exact
strings fail visibly. Existing money/dates cannot be overridden. Locked periods,
unqualified legacy history, foreign references and linked/excluded lines fail.
Repeated or conflicting matches cannot create another posting. Transfer and
undo/session operations retain separate qualification.

## Troubleshooting

### "MCP access requires a Pro plan"
Your organization is on the free plan. Upgrade at **Settings > Billing** to enable MCP access.

### "Invalid access token"
Your access token has expired. MCP clients should automatically refresh tokens using the refresh token. If this persists, disconnect and reconnect the MCP server.

### "Not a member of this organization"
Your user account has been removed from the organization. Ask an admin to re-add you.

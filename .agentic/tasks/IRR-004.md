# IRR-004 - Prepare the qualified opt-in IRR release candidate

## Objective and implementation scope

Prepare the concrete code/configuration candidate that can enable functional
IRR after financial, security and restore qualification. Update the code-owned
readiness gate only when attributable evidence for this exact candidate supports
it. Preserve a default-off operator flag, strict configuration validation and
all existing history/authorization protections. This task prepares the candidate
for REL-001/REL-002; it does not authorize deployment or switch an operator flag.

All technical reviews must be honestly attributed to Codex. Preserve Stripe
under DEC-008, integer minor units, canonical money contracts and existing data.
No new human-release or independent native-language approval is implied.

## Inputs

- [IRR selection qualification](IRR-003.md), [readiness map](../registries/IRR_READINESS.md), [QA-001](QA-001.md), [QA-002](QA-002.md), [QA-005](QA-005.md).
- [Release preparation](REL-001.md), [candidate approval](REL-002.md) and [rollout policy](../docs/ADR-003-LOCALE-AND-CURRENCY-ROLLOUT.md).
- [Release requirements](../sources/SOURCE.md#required-files-and-pull-request-sequence).

## Acceptance criteria

- [ ] Resolve every mandatory financial/security/restore finding for the exact candidate and link attributable evidence; do not infer readiness from tracker completion or rewrite historical evidence.
- [ ] Implement and verify the reviewed code readiness change with IRR_PRODUCTION_ENABLED default false; explicit true permits qualified IRR and malformed values fail startup before database use.
- [ ] Verify enabled and disabled policy parity through settings, REST, MCP and affected background services, including non-IRR regressions and immutable-history failures.
- [ ] Prepare the exact commit/artifact, environment change, target-organization eligibility query, monitoring, stop/restore procedure and known limitations for REL-001/REL-002; leave runtime flags and organization currency unchanged.

## Verification

Run focused enabled/disabled rollout, settings and organization REST/MCP
regressions against the candidate plus the financial/recovery checks invalidated
by its diff. Run typecheck, lint, catalogs, money/controller validation and diff
checks. Keep builds, dev startup and production mutations outside this task.

## Handoff

Not started. REL-001 explicitly depends on this prepared candidate, so REL-002 can approve its exact code before IRR-005 performs any authorized activation.

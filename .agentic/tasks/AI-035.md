# AI-035 - Persist and execute the bounded metered provider loop

## Objective and implementation scope

Required child of AI-033. Consume AI-034's protocol boundary and AI-032's tool
operations in a real durable executor; pure protocol validation is not authorization.

## Inputs

[AI-033](AI-033.md), [AI-034](AI-034.md), [execution contract](../docs/AI_EXECUTION_CONTRACT.md), AI-005/022/029/030/032 source/evidence.

## Acceptance criteria

- [ ] Persist fenced provider attempts, original price/config/policy snapshots and stable provider-call/tool-operation associations before action. Enforce cumulative request/step/token/output/payload/time/cost ceilings with actual usage reservations and trusted settlement; unknown usage stays charged/reserved, and restart/clarification never resets limits.
- [ ] Integrate dependent tools, grounded safe final summaries/links and durable clarification/resume using live validated identity, permissions, configuration, kill switch and cancellation checks before every provider/tool action. Treat every text source as untrusted. Reject malformed/partial provider output before any dispatch, require separate approvals for sensitive operations and never replay uncertain writes.
- [ ] Retry only bounded transient provider/read attempts with new charged attempt identities and persistent ceilings; no implicit provider/model switch. Preserve known committed effects through cancellation/revocation and late callbacks. Minimize and redact public context; never collect private reasoning or use summaries as execution authority.
- [ ] Verify real REST/MCP/database execution with deterministic providers, competing/stale executors, lock waits, budget/quota/rate/config failures and separate-process crash/restart. Supply required migrations, drift checks, typecheck/lint and honest provider/hosting limitations; no live calls, build, dev server or activation.

# AI provider configuration boundary

AI-004 adds administration services, not live qualification or AI rollout. No production provider or model is selected. Keep `AI_PROVIDER_CALLS_ENABLED` absent or `false` until deployment/account eligibility and model/data-handling qualification are actually verified. Fixture success is not that qualification; see `AI_EXECUTION_CONTRACT.md` and AI-013.

External server configuration must be supplied through the deployment secret manager or ignored local environment, never database rows, browser code, prompts, tracked configuration or logs:

- `AI_APPROVED_PROVIDER_ENDPOINTS`: JSON array of exact canonical HTTPS POST endpoint URLs. Defaults to `[]`, denying every endpoint. No userinfo, query, fragment, custom port or IP literal is accepted. This deployment policy is separate from site-admin catalog settings; an administrator cannot approve an arbitrary endpoint through the application.
- `AI_CREDENTIAL_KEYS`: JSON object mapping a version identifier to a base64-encoded, independently generated 32-byte key. Do not reuse `AUTH_SECRET`, database passwords or provider credentials. Defaults to an empty ring, making secret writes/reads unavailable. AES-256-GCM binds ciphertext to organization and configuration IDs.
- `AI_CREDENTIAL_ACTIVE_KEY`: current key version for new credential writes. Keep old versions available during rotation. For each configuration, submit its replacement provider secret using the rotation operation and latest version; it is encrypted under the active key. Retire an old external key only after no configurations/backups needing recovery use it. Lost keys cannot decrypt stored credentials; rotate replacement credentials instead.
- `AI_PROVIDER_CALLS_ENABLED`: exact `true` is required for the bounded connection-test adapter; default is off. It neither enables conversation execution nor bypasses later organization policy, budget, approval, rollout or qualification checks. No business content is sent by the test.

Site administrators require a current site-admin **session** for global catalog reads/writes. Organization ownership, API keys and OAuth tokens cannot grant global authority. The catalog records approved model capabilities and evidence date, endpoint, timeout ceiling and delegated organizations. Organization owners or explicitly granted `manage:ai-providers` holders can configure only delegated providers, select approved models/timeouts and switch a single default atomically. An enabled setting alone is insufficient to make a call. Platform disablement, delegation withdrawal, missing encryption material, deleted/revoked credentials, disabled org config and missing call opt-in fail closed. Credential revocation is still allowed for an organization's own configuration after delegation withdrawal.

REST operations live under `/api/v1/ai/provider-catalog` (create; ID path for replacement; `/platform` for complete platform listing) and `/api/v1/ai/provider-configs` (list/configure; ID `/credential` PUT/DELETE for rotation/revocation; ID `/test` POST for connection test). The ordinary catalog GET returns only delegated entries, without other organizations' delegation IDs. Corresponding operation-specific tools are registered in `lib/mcp/tools/ai-providers.ts`. `AI_PROVIDER_ADMIN_TOOLS` and `PROVIDER_ADMIN_CHAT_ALLOWED=false` explicitly identify all operations for exclusion from AI-006's ordinary-chat registry; that registry is a later task. Administrative MCP management is retained.

Updates use expected versions; stale writes reject. Reads and writes return masked credential presence, never ciphertext or plaintext. Audit entries contain only entity IDs/version metadata. Provider data/errors are bounded and sanitized. Connection transport rechecks the external endpoint policy, rejects mixed private/public DNS, pins a validated public address while retaining TLS hostname verification, follows no redirects, limits requests/responses to 64 KiB and bounds wall time including DNS. Equivalent IPv6 spellings are canonicalized before range checks. The test submits fixed text with no tools, no parallel calls and `store:false`, and returns only sanitized status, versions, selected model, latency and usage after exact model validation. It does not establish zero data retention or service eligibility.

The first adapter is a conditional Responses-protocol connection boundary. Streaming/generation/run orchestration and policy/budget integrations remain AI-005/007; this task introduces no worker execution or automatic provider fallback. Administration UI and translation remain AI-010. No external keys, endpoints or live-call flags are populated by this task.

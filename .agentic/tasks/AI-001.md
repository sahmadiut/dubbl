# AI-001 - Define agent capability inventory and execution contracts

## Objective and implementation scope

Inventory existing site operations, MCP registrations, shared services and permissions. Define supported workflows and explicit gaps before exposing tools.

This task implements the owner-requested AI feature; it does not authorize deployment or relax existing financial/release gates.

## Inputs

- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Architecture and delivery plan](../docs/AI_AGENT_PLAN.md).
- Actual source and dependency evidence; verify current contracts before editing.

## Acceptance criteria

- [x] Publish a feature-to-tool matrix covering existing site domains, read/write permissions, exact-money contracts, side effects and unsupported operations; every exposed capability has a shared service and MCP operation.
- [x] Define run states, provider interface, approval policy, permission names, transcript visibility, data retention and rollout defaults in a reviewed architecture contract.
- [x] Select a first supported provider/model only after verifying current official API capabilities, availability for the deployment and data handling; record unresolved choices without inventing pricing or availability.

## Verification

Run meaningful focused checks for the changed contracts, including real REST/MCP authorization and disposable-database integration where relevant. Use typecheck and lint for application changes, catalog validation for localized UI, controller validation and diff checks. No full build or unrequested dev server. Record executed checks and limitations in unique evidence; do not substitute mocked-provider success for live-provider qualification.

## Inputs

## Acceptance criteria

- [x] Persist fenced provider attempts, original price/config/policy snapshots and stable provider-call/tool-operation associations before action. Enforce cumulative request/step/token/output/payload/time/cost ceilings with actual usage reservations and trusted settlement; unknown usage stays charged/reserved, and restart/clarification never resets limits.
- [x] Integrate dependent tools, grounded safe final summaries/links and durable clarification/resume using live validated identity, permissions, configuration, kill switch and cancellation checks before every provider/tool action. Treat every text source as untrusted. Reject malformed/partial provider output before any dispatch, require separate approvals for sensitive operations and never replay uncertain writes.
- [x] Retry only bounded transient provider/read attempts with new charged attempt identities and persistent ceilings; no implicit provider/model switch. Preserve known committed effects through cancellation/revocation and late callbacks. Minimize and redact public context; never collect private reasoning or use summaries as execution authority.
- [x] Verify real REST/MCP/database execution with deterministic providers, competing/stale executors, lock waits, budget/quota/rate/config failures and separate-process crash/restart. Supply required migrations, drift checks, typecheck/lint and honest provider/hosting limitations; no live calls, build, dev server or activation.

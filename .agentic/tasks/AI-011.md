# AI-011 - Build scoped AI usage and operations dashboard

## Objective and implementation scope

Provide usage analytics and run monitoring within existing admin navigation.

This task implements the owner-requested AI feature; it does not authorize deployment or relax existing financial/release gates.

## Inputs

- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Architecture and delivery plan](../docs/AI_AGENT_PLAN.md).
- Actual source and dependency evidence; verify current contracts before editing.

## Acceptance criteria

- [ ] Show token categories, estimated cost by currency, requests, tool calls, success/failure, latency, active runs and quota remaining with date/user/organization/provider/model filters and scoped export.
- [ ] Users see their own permitted usage, organization managers see authorized organization totals, and site administrators see authorized aggregate usage; transcript audit access is a separate permission.
- [ ] Authorized administrators configure per-user/organization limits, inspect redacted errors and cancel runs or disable execution; UI and REST/MCP policy controls agree.
- [ ] Test empty states, missing provider usage, accurate paginated totals, exact cost display, English/Persian RTL behavior and unauthorized drill-down/export.

## Verification

Run meaningful focused checks for the changed contracts, including real REST/MCP authorization and disposable-database integration where relevant. Use typecheck and lint for application changes, catalog validation for localized UI, controller validation and diff checks. No full build or unrequested dev server. Record executed checks and limitations in unique evidence; do not substitute mocked-provider success for live-provider qualification.

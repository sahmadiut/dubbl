# AI-034 - Validate bounded provider requests and complete tool calls

## Objective and implementation scope

Required child of AI-033. Implement the pure Responses protocol boundary before
the metered executor can consume model output. Reuse reviewed tool schemas; no
network calls, execution authority, persistence or rollout activation is introduced.

## Inputs

[AI-033](AI-033.md), [execution contract](../docs/AI_EXECUTION_CONTRACT.md),
lib/ai/tool-catalog.ts, lib/ai/provider-security.ts and current official protocol documentation.

## Acceptance criteria

- [x] Construct bounded stateless serial-function requests from server-selected capabilities, reviewed tool names and bounded public history. Preserve strict nested schemas, optional/default semantics and exact money strings; reject unsupported capabilities, roles, unmatched calls/results, oversized/deep inputs and caller-injected request options. Return conservative input/output reservations without claiming a qualified tokenizer.
- [x] Validate the entire completed response against the original model/tool set and ceilings before returning any call. Require complete unique call IDs and exact arguments, reject unknown items/statuses, malformed/duplicate-key JSON, unapproved tools and oversized/deep output. Extract usage independently so invalid content cannot become free usage; retain unknown usage explicitly. No partial output, private reasoning, provider diagnostics or model-authored record links become confirmed results.
- [x] Exercise deterministic dependent-turn fixtures and adversarial output/history/schema/usage cases against the actual reviewed catalog; pass focused tests, typecheck/lint, capability/coverage and controller/diff checks. Document the internal contract and remaining metered-loop/process/streaming integration obligations honestly.

## Verification

Pure protocol tests exercise actual catalog schemas without mocks of that boundary.
No database/schema/REST/MCP change is required by this internal pure function.
AI-035/036 and parent AI-033 retain real disposable-database and REST/MCP execution acceptance.

## Handoff

Implemented lib/ai/provider-protocol.ts, deterministic actual-catalog tests and
AI_PROVIDER_PROTOCOL.md. Evidence: AI-034-attempt-1.md and honest Codex self-review
AI-034-review-1.md. The pure boundary validates bounded immutable requests and
complete unique calls while retaining known/unknown usage independently. It has
no network/DB/permission/dispatch authority. AI-035 must integrate raw response
transport, durable metering/call-operation binding, live guards, actual tools,
clarification and safe summaries; AI-036 owns the polling process and provisional
observation. AI-033/031/023/007 retain independent acceptance. No live calls,
rollout flags, Stripe, public routes/tools or database schema changed.

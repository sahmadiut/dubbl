# AI-042 - Persist versioned sensitive action previews and exact batches

## Objective and implementation scope

Build on AI-041 while retaining its preview-only nature. Business approval conditions must be evaluated through existing domain policy without bypass or disclosure of unauthorized identities.

## Inputs

- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Product experience](../docs/AI_PRODUCT_EXPERIENCE.md), [AI-008](AI-008.md), and actual dependency source/evidence.

## Acceptance criteria

- [ ] Define and document a finite supported posting, payment, deletion and external-sending adapter set from actual shared domain operations; unsupported actions and credential/security/provider/role changes stay unavailable. Supply trusted domain-derived business previews for each supported action.
- [ ] Persist full validated execution arguments separately from bounded display, binding actor, organization, run/step, catalog/action version, exact resource snapshot, selection, dependency graph and expiry. Schema changes include generated Drizzle migrations.
- [ ] Expose shared REST/MCP retrieval and revision with current permission checks and finite unavailable/stale/expired/recovery codes. Revising arguments, resources or selected items regenerates versions and invalidates old authority.
- [ ] Each batch shows every selected effect with exact separate currency totals, recipients and irreversible effects. Validate dependency closure, bounds and acyclicity; no implicit sensitive selections or execution from preview.
- [ ] Verify disposable-database REST/MCP/SQL scope, retention, concurrent revision, stale selection/version, cross-tenant records and no execution on preview/revision.

## Verification

Run focused real transport/database checks where relevant, typecheck, lint, tool-coverage audit, controller validation and diff checks. Use a disposable explicit loopback TEST_DATABASE_URL; no full build, dev server or live-provider qualification claim.

## Handoff

Not started. AI-008 remains the independent integration parent; no deployment or activation is authorized.

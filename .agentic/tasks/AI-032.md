# AI-032 - Fence durable tool operations and preserve uncertain effects

## Objective and implementation scope

Required child of AI-031. Implement the durable tool action boundary before a provider loop can safely use it. Existing storage helpers are not worker authorization. No provider loop, polling process, live provider or rollout qualification is claimed by this child.

## Inputs

[AI-031](AI-031.md), [execution contract](../docs/AI_EXECUTION_CONTRACT.md), AI-022/029/030 source and evidence.

## Acceptance criteria

- [x] Implement internal lease-fenced prepare/dispatch/settlement using stable operation keys, exact validated argument digests and ordered transactional events; reject stale/foreign leases and conflicting replays, and never dispatch an operation twice.
- [x] Recheck live identity, provider/policy snapshots, runtime/kill switch, deadline, cancellation, tool schema and permissions at dispatch; bound steps and cumulative payloads, retaining budget/deadline/operation identity on continuation and recovery.
- [x] Derive record provenance only from actual registered tool results, persist safe bounded outcomes, preserve partial effects during cancellation/revocation, and leave ambiguous writes for reconciliation without automatic replay.
- [x] Verify real registered tools, progress REST/MCP and independent disposable database assertions, competing/stale executors, lock waits, cancellation, and a separate-process crash after a committed write. Pass typecheck/lint, schema/capability/coverage drift and controller/diff checks; document the remaining provider-loop responsibilities.

## Verification

Disposable PostgreSQL, actual linked registered MCP business tools, route/MCP observation, separate-process dispatch and crash recovery. No live provider, build or dev server.

## Handoff

# AI-023 - Execute metered bounded provider and dependent tool loops

## Objective and implementation scope

Bounded child of AI-007. Child completion does not accept the integration parent. Build on AI-022 lifecycle primitives and the existing AI-002 through AI-006 contracts. No live provider qualification or rollout is inferred.

## Inputs

- [Product experience contract](../docs/AI_PRODUCT_EXPERIENCE.md): normative journeys, UI states and observable UX acceptance.
- [AI-007](AI-007.md), [execution contract](../docs/AI_EXECUTION_CONTRACT.md), and actual dependency source/evidence.

## Acceptance criteria

- [x] Implement explicit worker entrypoint with polling, graceful shutdown and lifecycle lease ownership; deterministic fake provider verifies dependent tools, grounded final links and clarification.
- [x] Enforce current identity, policy, kill switch, step/request/token/output/time/cost limits before each provider/tool action; preserve configured provider snapshots and usage reservations with trusted callbacks.
- [x] Persist ordered idempotent steps and events, safely retry bounded transient reads/provider attempts, reconcile uncertain writes without duplicate effects, and retain partial completion on cancellation/restart.
- [x] Treat all user/document/tool text as untrusted and export action summaries without private reasoning; real REST/MCP/database and deterministic provider tests verify races, failures, disconnection and recovery.

- [x] Define and implement the missing shared UI/MCP contracts for safe progress/result reads and clarification submission/resume, with strict described schemas, own/org scope, expected versions and idempotency. Content-free cursor events notify of changes; authorized display data is fetched separately, with bounded streaming/polling and no hidden dispatch on reconnect.
- [x] Persist awaiting-input questions and scoped candidate references; accept only the pending version's answer, recheck access and safely queue continuation without resetting execution budgets or replaying effects. Distinguish input from approval and discard invalid/stale choices; do not rely on model conversation memory as authority.
- [x] Return safe structured business outcomes, error/recovery codes and actual record references for AI-027. Cover stop acknowledgement, worker-unavailable/queue conditions, rate/quota exhaustion and reconciliation-required outcomes; never fabricate queue positions, completion percentages, rollback or success.
- [x] Test provisional assistant streaming versus persisted confirmed results, cursor loss/reconnect, delayed responses, cancellation during an effect and bounded long histories. Review stream content under current permissions; no private reasoning, secrets or execution authority in public events.

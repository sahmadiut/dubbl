# AI-024 - Guide provider setup and expose scoped readiness

## Objective and implementation scope

Improve the existing provider configuration UI without rewriting AI-010's accepted record. Connect the saved provider/model, credential, pricing, budgets and policy prerequisites into a guided, resumable setup flow. Primary source surfaces: components/ai/management.tsx, management-forms.tsx, lib/ai/admin-client.ts and existing provider/usage services.

## Inputs

- [Owner requirements](../sources/SOURCE.md#ai-agent-and-administration-owner-extension).
- [Product experience contract](../docs/AI_PRODUCT_EXPERIENCE.md) and [delivery plan](../docs/AI_AGENT_PLAN.md).
- Actual source, current shared REST/MCP services and dependency evidence. Verify interfaces before implementation.

## Acceptance criteria

- [ ] Provide a scoped readiness service with REST/MCP parity and strict described schemas. Return safe blocker/status codes and authorized next actions for catalog/delegation, credentials, model, immutable price, organization/member budgets, tool policy and runtime availability; never return secret material or internal deployment values.
- [ ] Implement the administration journey in AI_PRODUCT_EXPERIENCE: approved provider/model selection, credential entry, price/budget links, policy links and explicit metered test. Distinguish configuration saved, last tested version, runtime disabled and provider qualification pending; no automatic calls, enablement or invented provider/price defaults.
- [ ] Invalidate displayed test/readiness evidence after relevant configuration, credential, price, policy or membership changes. Show sanitized actionable failures, last-tested time/version and costs/usage when known; a successful connection test cannot imply rollout eligibility.
- [ ] Preserve non-secret input on recoverable errors and unrelated saves, associate field errors/help, handle version conflicts and discard late responses on org switch/unmount. Keep site-only catalog actions usable under current site-admin sessions without introducing organization-derived global authority.
- [ ] Test new/returning admins, absent providers/prices/member budgets, withdrawn delegation, revoked access, stale versions and failed tests in both locales and narrow layouts; real service tests enforce scoped REST/MCP parity. Record remaining native/runtime qualification honestly.

## Verification

Run focused behavior/accessibility and real shared-service REST/MCP checks for changed contracts, disposable-database tests where relevant, typecheck/lint and catalog checks for application changes. Record exercised viewports/locales/themes and observable outcomes. Use existing authorized runtime or a component harness; no full builds or unrequested dev server. No live calls or deployment inferred. Run controller validation and diff checks. Split through the controller before implementation if the scope exceeds a coherent change; the parent retains independent acceptance.
